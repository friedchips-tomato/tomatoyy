### 3.2 为什么要做降级（现场话术）

> 「停车数据是会断的——传感器掉线、网络抖动、运营台忘记更新。我们的做法不是让模型硬撑，而是定一条**固定的降级链**：能用模型就用模型；数据不全就退到更粗但更稳的统计基线；最后连最近一个已知值都没有，就**不给数字**。核心原则是：**宁可给一个有出处的粗答案，也不给一个看起来精确的假数字。**」
>
> 补充：「每一级降级都会在 `forecast.method` 和 `degrade_reason` 里留痕，页面和月报都能看到『这个数字是怎么来的』，是 D0 模型给的还是 D3 复制来的，一目了然。」

### 3.4 线上"数据过期"怎么表现

> 出处：设计文档 `design/parking-forecast/03-特征降级与训练回测.md §2.1`（属设计口径，**不是**本次回测产物；具体阈值不在本页引用，需要时请当场翻该文档）。

## 4. 泄漏自检与约束（§4 原文要点，一条一条）

出处：`report.md §4` + `metrics.json:leakage_self_check` / `metrics.json:split`。

1. **泄漏自检：通过**（`metrics.json:leakage_self_check.ok` = `true`）。做法是抽 100 个预测时刻（`checked=100`，`metrics.json:leakage_self_check.detail` 原文「checked=100 特征与预测在未来观测删除后逐位不变」），把该时刻**之后的所有观测删掉**，重新算特征和预测，结果必须**逐位完全相同**——相同就说明模型没有偷看未来。
2. **切分 embargo 检查：通过**（`report.md §4`）。切分点后各留 **24.0 小时**隔离带（`metrics.json:split.embargo_hours` = 24.0），因为预测 horizon 最远到 60 分钟，不隔离会让目标时刻跨过切分点造成标签泄漏。切分本身按**时间顺序**、不打散（`metrics.json:split.train / .valid / .test`，`report.md §0`：train 2026-04-01~2026-04-07 → valid 2026-04-09~2026-04-10 → test 2026-04-12~2026-04-14）。
3. **Python/JS 逐位一致性**：由 `tests/test_consistency.py` + `node --test runtime/test/` 断言（500 条输入）（`report.md §4` 原文）。
4. **特征构造的硬规则**（设计口径，`design/parking-forecast/03-特征降级与训练回测.md §3.1`）：任何特征、任何基线统计量，**只能用 `ts <= issued_at` 的数据计算**；同周期基线的统计窗口右端点 `<= issued_at`；回测时 `cutoffs = issued_at`，线上 `cutoffs = min(now, issued_at)`。
5. **缺失指示位不静默伪造**（同文档 §1）：所有可能缺失的特征组都配 `*_missing` 布尔位参与训练——把"没数据"编码成某个数值让模型猜，等于静默伪造；指示位让模型至少能区分"确实如此"与"不知道"。

**现场话术**：「我们防泄漏不是靠自觉，是靠两件事——一是把"允许看到的最晚观测时刻"做成函数参数并强制传参，二是自动化自检：删掉未来数据后预测必须一位不差地相同。切分点还留了 24 小时隔离带，因为我们要预测 60 分钟后，不隔离会跨过边界偷看答案。」

## 6. 四个必答问题准备

### ① 「这个 MAE 怎么算的？」

**建议回答**

> 「MAE 是绝对车位误差，`mean(|pred − actual|)`，单位是**车位**——预测 24 个车位、实际 27 个，误差就是 3 个车位。它衡量的是'差多少个位'。
> 但需求书写的是'≤20%'，而 MAE 的天然单位是车位，百分比需要**一个分母**，分母不同结果差很多。我们把四个候选口径都列出来了：A 相对平均余位、B 相对总车位、C 空置率 MAE、D WAPE。**主口径取 D（WAPE）**，因为它聚合稳定，不会像 A 那样在满位时段分母趋 0 时爆炸。
> 现场主口径：模型 MAE **1.8733** 车位、WAPE **0.0702**（report 上写 7.02%）、MAPE **0.1248**，最强基线 `last_known` 是 MAE 2.2096。
> 另外一个必须披露的点：MAPE 只在真实余位大于 0 时才有定义，满位时段要排除——本次被排除的比例是 **0.0**。」

**不能说的话**

- ❌「MAE 1.87 个车位 ÷ 100 个车位 = 1.87%，所以我们远超 20%。」（混用了口径 B 和主口径 D）
- ❌「我们的误差已经通过验收 / 指标符合要求。」（分母还没书面确认，且是合成数据）
- ❌ 报不出「选 WAPE 的理由是它更稳健、不随分母趋零爆炸」。

**如果被追问到数据来源**（口径/指标的定义从哪来）

> 「指标定义不是我们自己定的，是方案文档 `design/parking-forecast/03-特征降级与训练回测.md §3.4/§3.5` 里定死的口径表，机器可读版本在 `artifacts/metrics.json` 的 `denominator` 段（`chosen` 字段写的就是 `wape (口径 D)`，还记了选它的 `reason`）。四个分母口径同时上报，是因为需求方的原需求只写了'MAE ≤ 20%'而 MAE 没有分母——我们把选择权留给需求方书面确认，报告首页因此写明'在需求方书面确认前不自称达标'。」

---

### ② 「数据是真实的吗？」

**建议回答**

> 「不是，**这份数据是合成的**（`source=synthetic`）。它是用生成器造的 14 天数据，目的只有一个：**证明整条管线是通的**——特征构造、模型训练、降级链、泄漏自检、Python/JS 一致性，代码路径全部跑通。
> 所以这份报告证明的是**工程管线可用**，**不代表模型精度**。正式精度指标必须由真实历史数据加上现场校验得出，这是两件事，我们没有混淆。

### ③ 「为什么用 XGBoost / 随机森林而不是 LSTM？」

**建议回答**（**第一句必须先纠正前提**）

> 「先纠正一下前提：**我们这次交付的模型不是 XGBoost、也不是随机森林，是 `kind=linear` 的增量岭回归**——每个 horizon 一个系数向量，加显式标准化，再加残差分位数区间 p10/p90（`report.md §0`，`artifacts/model.json` 的 `kind` 字段就是 `linear`）。设计里 XGBoost/GBDT 是候选 M1 的另一种实现，我们选了其中的线性分支。
> 选它的理由有三条：
> 第一，**运行时是浏览器里的 JS，不能跑 sklearn**。我们要求训练产物能被 JS 逐位复现，所以模型类型必须可导出——线性模型导出系数即可，GBDT 要导出成 if/else 树数组再写解释器。
> 第二，**数据量小**。现在只有 14 天合成数据，未来真实历史数据也是有限的，深度模型在这个量级上容易过拟合；LSTM 还需要成段的时序样本和更重的训练，收益不确定。
> 第三，**可解释、可交付**。线性模型的每个特征权重是看得见的，页面上的'预测余位'能被运营方追问'凭什么'，而残差 p10/p90 区间让用户知道这个数有多可信。
> 诚实的补充：GBDT 在同等特征下通常比线性模型更强，等真实数据到位、样本量上来之后，**我们会重跑 M1 的 GBDT 分支并与现在这套线性模型对照**，用同一套回测口径决定谁上线。」

**不能说的话**

- ❌「我们用了 XGBoost / 随机森林。」（事实不符，模型是 `kind=linear`；被追问报 `artifacts/model.json` 一看就穿帮）
- ❌「深度学习效果更好 / LSTM 精度更高」。」（本项目没有 LSTM 的任何对比数字）
- ❌「线性模型已经是最优选择，不需要再换。」（等于封死了后续用真实数据迭代的口子）

**如果被追问到数据来源**

> 「模型选择依据的是**数据量**和**运行时约束**，不是数据来源的偏好：线性模型每个 horizon 只有一组系数，可以在浏览器里逐位复现，我们用同一批 500 条输入做了 Python/JS 逐位一致断言（`report.md §4`）；等真实数据接入、样本量上来后，这个比较要重做。」
