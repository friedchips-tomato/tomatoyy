# 江门长堤风貌街 · 像素地图导览 · 新方案清单

> 地点：广东省江门市蓬江区，长堤历史文化街区（长堤风貌街），沿蓬江北岸，全长约 1.5 km。
> 主形式：**竖屏微信小程序里的一张可交互像素地图**。路线、讲解、预约、停车、反馈都以「地图上的弹层」出现，不再是独立的列表页面。
> 分工：**Claude 指挥 + 写全部文字**；出图交给 **GPT（ChatGPT 网页生图）**，写代码交给 **GPT（Codex）**；现场照片与需求方数据由你提供。
> 上一版《方案清单.md》保留作功能参考，本清单取代它的页面结构。

---

## 一、分工规则

| 角色 | 负责 | 不负责 |
|---|---|---|
| **Claude（指挥）** | 拆任务、写给 GPT 的任务书和生图提示词、定验收标准、审查 GPT 交回的图和代码、**写全部文字**（点位介绍、讲解词、卡片文案、界面文案、任务说明、技术报告） | 不直接画图、不直接写小程序代码 |
| **GPT · 生图** | 像素底图分段、建筑精灵图、代表物小图标、人物 NPC、UI 像素图标、电子小卡 | 不自行决定建筑位置和外观，一律按 Claude 给的定位图和你给的照片画 |
| **GPT · Codex** | 小程序前端、像素图后处理脚本、拼接脚本、坐标换算、后端接口、数据导入 | 不自行编写史实文字，文字一律从 Claude 交付的文案文件读取 |
| **你** | 确认点位名单、现场拍照或提供照片、对接需求方数据、确认样张 | — |

每个任务都按同一个流程走：**Claude 写任务书 → GPT 执行 → Claude 对照验收标准审查 → 关键样张给你确认 → 再批量**。

### 2.2 补齐点位要做的事

- [ ] **你**：向需求方要五类数据中的「点位与文化资源数据」，其中应有点位编号、名称、经纬度（CGCS2000）、类别、保护等级。需求书要求覆盖 ≥ 100 个点位。
- [ ] **你**：在腾讯地图上逐个核对上表点位，记下坐标；对需求方数据没有覆盖的点位也一样处理。
- [ ] **你**：现场拍照，或从需求方素材里找照片。每个重点建筑拍**正立面 1 张 + 斜 45° 1 张 + 一个细节（窗、山花、招牌）**，GPT 照着画。
- [ ] **Claude**：把所有点位整理成 `data/points.json`（字段见第五节），统一编号，标出「重点建筑（单独做精灵图、可点亮）」和「背景建筑（画进底图）」。
- [ ] **Claude**：为每个重点建筑选一件**代表物**（如侨批、招牌、老物件）。只用史料里能找到依据的，找不到依据的空着，不编造。

> 底图的街道、河岸、建筑轮廓也需要真实依据。可选来源：需求方提供的街区平面图（首选）、天地图影像描摹、OpenStreetMap 建筑轮廓（需署名）。像素图定位为「示意导览图」，不显示经纬度网格；上线前向需求方确认是否涉及审图要求。

## 三、像素地图怎么做（竖屏专用）

### 3.1 关键设计决定

| 决定 | 内容 | 理由 |
|---|---|---|
| **地图转 90° 竖放** | 1.5 km 长街改为从上到下排列，蓬江在屏幕一侧，上下滑动浏览；右上角放指南针，标明真北方向 | 长街本来是横向的，横着放在竖屏上会很窄，竖放后单手上下滑就能逛完整条街 |
| **视角** | 3/4 斜俯视像素风（参考需求文档里那张像素办公室截图），能同时看到屋顶和骑楼立面 | 骑楼的特征全在立面上，纯俯视看不出来 |
| **分层，不画成一整张图** | 底图层（地面、街道、河、背景建筑）＋重点建筑精灵层＋人物/图标层＋交互热区层 | 一整张生成图无法单独点亮建筑，改一处就得重画整张，位置也难对准 |
| **分段生成** | 整条街按约 250 m 切成 6 段，每段单独生成，相邻段重叠 10%，由 Codex 拼接 | 一张图塞进 1.5 km 细节会失真，分段更容易对准真实位置 |
| **黑白与彩色两版由脚本生成** | GPT 只画彩色版，灰度版由 Codex 脚本转换 | 两版完全对齐，并且省一半生图次数 |
| **真像素后处理** | GPT 出的图先缩到目标像素尺寸（最近邻），再压到统一调色板，最后整数倍放大导出 | ChatGPT 出的「像素风」并不是真像素网格，不处理的话放大后发糊、颜色不统一 |

### 3.2 生产步骤

| 步骤 | 负责 | 产出 | 验收标准 |
|---|---|---|---|
| M1 定位底稿 | Claude 写规格 → Codex 出图 | 一张竖放的线稿定位图：河岸线、街道、建筑轮廓块、点位编号；按比例尺生成，分 6 段 | 用 3 个以上控制点（如两座桥、启明里）检验，位置误差 < 2 个格子 |
| M2 风格样张 | Claude 写提示词 → GPT 生图 | 一段（约 250 m）的彩色像素底图样张 | **你确认风格**：色调、视角、骑楼细节、文字是否清晰（底图上不放文字，名称由程序叠加） |
| M3 统一调色板 | Codex | 从样张提取 32–48 色调色板，形成 `palette.json` | 之后所有图都压到这套颜色 |
| M4 底图 6 段 | Claude 每段写提示词，附定位图与照片 → GPT 生图 | 6 段底图 | 每段叠在定位图上检查：街道和河岸走向一致，重点建筑空位留对 |
| M5 重点建筑精灵 | Claude 每栋写提示词，附照片 → GPT 生图 | 每栋一张透明底 PNG，演示版 8–12 栋，正式版 20–30 栋 | 立面特征与照片对得上（拱券数、层数、窗型、颜色）；尺寸与定位图轮廓一致 |
| M6 代表物与小卡 | Claude 写提示词 → GPT 生图 | 代表物像素图标（如侨批）、电子小卡卡面 | 与点位一一对应，卡面风格统一 |
| M7 人物与图标 | Claude 写提示词 → GPT 生图 | 游客小人（4 个方向的行走帧）、讲解员 NPC、停车 P 牌、码头船只、UI 像素图标 | 帧尺寸统一，动作连贯 |
| M8 后处理与拼接 | Codex | 全部素材做真像素化，转灰度版，拼出完整底图并切瓦片 | 拼缝看不出来；放大 3 倍边缘不发糊 |
| M9 坐标对齐 | Codex | 经纬度 → 像素坐标的换算参数（用控制点做最小二乘仿射） | 所有点位换算后落在对应建筑上；游客小人随定位移动 |

## 四、小程序：一张地图 + 弹层

### 4.1 主界面（打开就是像素地图）

```
┌──────────────────────┐
│ 长堤风貌街    中/EN/粤 🧭 │  顶栏：语言切换 + 指南针
│ 已点亮 3/12  ▓▓░░░░░  │  点亮进度
│                      │
│   像素地图（上下滑动） │  双指缩放，三档：全街 / 街段 / 建筑
│   ■ 黑白建筑 = 未探索  │
│   ■ 彩色建筑 = 已点亮  │
│   ● 游客小人 = 我的位置 │
│   ⋯ 虚线 = 当前路线    │
│                      │
│ [♪ 正在讲解：××  ‖ ]  │  迷你播放条（讲解时出现）
│ [路线] [扫码] [服务] [我的] │  底部 4 个按钮，均以弹层打开
└──────────────────────┘
```

### 4.2 地图上能点的东西

| 编号 | 点什么 | 发生什么 | 优先级 |
|---|---|---|---|
| X01 | 重点建筑 | 建筑轻微弹跳，底部弹出卡片：代表物图标、名称、年代、一句话介绍、「听讲解」「详情」「去这里」 | P0 |
| X02 | 卡片里的「详情」 | 弹层升到全屏：照片、文字介绍、关联人物与事件、史料来源、打卡按钮、预约讲解员、附近停车 | P0 |
| X03 | 代表物图标 | 放大展示代表物，配一段 30 秒内的小故事 | P1 |
| X04 | 打卡成功 | 建筑由黑白渐变为彩色，掉落一张电子小卡，进度条 +1 | P0 |
| X05 | 讲解员 NPC（站在服务点） | 弹出可约讲解员列表与时段，进入预约流程 | P1 |
| X06 | 停车 P 牌 | 显示余位条（绿 / 黄 / 红）、未来 1 小时预测、步行到街区的距离；「设为路线起点」 | P1（演示用示范数据并标注） |
| X07 | 游客小人 | 显示附近 3 个点位；离点位很近时头顶冒出「!」，提示可打卡和讲解 | P1 |
| X08 | 关联连线 | 在建筑详情里点「关联人物/事件」，地图上用像素虚线连到相关建筑，形成故事线 | P1 |
| X09 | 码头、船只、街边小物 | 小彩蛋动画，不承载功能 | P2 |
| X10 | 昼夜变化 | 按本地时间切换白天和夜晚配色（夜间骑楼亮灯） | P2 |

### 4.3 底部四个按钮的弹层

| 按钮 | 弹层内容 | 来源（上一版清单） |
|---|---|---|
| 路线 | 兴趣、时长、出行方式三步选择 → 三条候选路线（在地图上用三种颜色的虚线预览）→ 采纳后地图进入「游览中」：显示下一站、进度、到达提示 | P02、P03、P07 |
| 扫码 | 扫二维码 / 碰 NFC / 拍照识别，识别成功后地图自动滚动到该建筑并完成打卡 | E01、E02、P13 |
| 服务 | 讲解员预约、停车比较、我要反馈（诉求提交与追踪） | P15–P23 |
| 我的 | 卡册、点亮进度、我的预约、我的诉求、设置 | P25–P28 |

### 4.4 技术要点（写进给 Codex 的任务书）

- [ ] 原生微信小程序；像素地图用 **Canvas 2D** 绘制，关闭图像平滑，保证放大后颗粒清晰。
- [ ] 底图按瓦片加载，只画屏幕内及上下各一屏的瓦片；首屏 ≤ 2s。
- [ ] 热区用每栋建筑的多边形判断点击，不用矩形，避免骑楼相连时误触。
- [ ] 定位：腾讯地图返回 GCJ-02 坐标，需求方数据是 CGCS2000，入库前统一换算；再用 M9 的参数换成像素坐标。
- [ ] 拒绝定位时，游客小人隐藏，其余功能照常可用。
- [ ] 所有文字从 Claude 交付的文案文件读取，代码里不写死任何史实内容。
- [ ] 分包：主包只放地图与建筑详情；路线、服务、卡册各自分包。

## 五、数据结构（Claude 定义，Codex 实现）

`data/points.json` 每个点位一条：

| 字段 | 说明 | 填写人 |
|---|---|---|
| `point_id` | 统一编号，如 CD-A01 | Claude |
| `name` / `name_en` / `name_yue` | 名称三语 | Claude |
| `category` | 历史建筑 / 文物 / 非遗 / 商业 / 公共服务 / 停车 | Claude |
| `lat` / `lng` | 经纬度，注明坐标系 | 你（来自需求方或现场核对） |
| `map_px` | 在像素底图上的锚点坐标 | Codex（M9 换算） |
| `hotspot` | 点击热区多边形 | Codex |
| `sprite` / `sprite_gray` | 彩色和灰度精灵图路径 | Codex |
| `token_item` | 代表物名称与图标 | Claude 定名，GPT 出图 |
| `card` | 电子小卡卡面路径与文案 | Claude 写文案，GPT 出图 |
| `intro` | 一句话介绍 + 详情正文（三语） | Claude |
| `guide_script` | 讲解词：简短 30 秒 / 标准 90 秒 / 深度 3 分钟 | Claude |
| `relations` | 关联人物、事件、建筑（只填有史料依据的） | Claude |
| `sources` | 每条史实的出处 | Claude |
| `photos` | 现场照片路径 | 你 |

打开小程序 → 看到整条长堤的像素街景，建筑都是黑白的 → 选「侨乡历史 · 60 分钟」，地图上出现三条路线 → 采纳一条 → 走到第一栋建筑（扫码或到达）→ 建筑变成彩色，掉落小卡 → 听 AI 讲解，切换粤语 → 点「关联人物」，地图上连线到另一栋建筑 → 点讲解员 NPC 预约 → 打开「我的」看卡册。

## 八、开工前要你决定或提供的

1. 演示版选哪 12 个点位（建议：两座桥 + 海关旧址 + 博物馆长堤分馆 + 启明里 + 水埠头 + 新市路 + 墟顶街 + 4 栋代表性骑楼）。
2. 需求方能不能提供街区平面图或建筑轮廓数据；没有的话，用天地图影像描摹还是 OpenStreetMap。
3. 重点建筑的照片：你去现场拍，还是需求方提供。
4. 「GPT 写代码」用 Codex 是否可以；生图走你已登录的 ChatGPT 网页。
5. AI 讲解的语音：用 GPT 的语音合成做演示，还是另选支持粤语的 TTS（需求书要求能离线或专有云部署）。
