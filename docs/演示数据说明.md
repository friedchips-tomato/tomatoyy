# 演示数据说明

答辩前运行 `scripts/seed-demo-cases.mjs`，可在本检出的独立演示库中准备 13 条工单，用于展示值班队列、闭环进度和内部月报。

## 1. 数据范围

每条工单的描述以「【演示】」开头，联系方式使用 `demo-<序号>@example.test`。脚本通过接诉即办 HTTP 接口提交和流转工单。

| 项目 | 数量 | 说明 |
| --- | --- | --- |
| 工单 | 13 条 | 固定使用 `demo-seed-01` 至 `demo-seed-13` |
| 状态 | 10 种 | 待受理、待分派、已分派、处理中、待复核、待评价、已关闭、待补充、不予受理、补办待审核 |
| 诉求类型 | 6 类 | 环境卫生、设施损坏、停车问题、街面维护、公共秩序、噪声扰民 |
| 已评价并关闭 | 3 条 | 提交、受理、分派、办理、复核发布、三维评价、确认解决 |

## 2. 队列计数

空库完成造数后，值班运营台有 6 个非空队列。

| 队列 | 接口字段 | 刚造数后的数量 |
| --- | --- | ---: |
| 待受理 | `pending_intake` | 1 |
| 待分派 | `pending_assignment` | 1 |
| 处理中 | `processing` | 3 |
| 待复核 | `pending_review` | 1 |
| 补办待审核 | `pending_reopen` | 1 |
| 临期 | `due_soon` | 1 |
| 超时 | `overdue` | 0 |

分派时必须填写将来的期限。临期示例分派约 2 小时后进入「超时」，其他已分派的活跃工单约 72 小时后到期。重复运行保留原分派期限，队列会随时间变化。

## 3. 启动与生成

在 Windows PowerShell 5.1 和 Node.js 22.17 或更新版本下，先在当前终端设置本地合成凭据。T16 启动器读取 `CHANGDI_RECEIPT_KEY`、`CHANGDI_INTEGRATIONS_JSON`、`CHANGDI_STAFF_JSON` 和 `GUIDE_INTAKE_TOKEN`。接单来源设为 `local-demo`，导览接单使用该来源的 token。工作人员配置要包含 `duty`、`handler`、`supervisor`，承办人与主管使用相同的 `department`。继续使用同一个库时，保持启动时的回执密钥稳定。

从仓库根目录执行。示例使用三个备用端口，启动前确认它们空闲。

```powershell
& .\scripts\答辩启动.ps1 -BackendPort 23400 -StaticPort 28931 -BridgePort 28932
& .\scripts\答辩启动.ps1 -Status
node .\scripts\seed-demo-cases.mjs --port 23400 --confirm-demo
```

种子脚本从当前终端的 `CHANGDI_INTEGRATIONS_JSON` 和 `CHANGDI_STAFF_JSON` 读取启动时使用的同一套接单方与工作人员凭据。如果启动时通过 `-CredentialsFile` 配置，在运行种子脚本前也要将这两项加载到当前终端环境。统计和错误日志只输出配方编号、工单状态、汇总和固定诊断。

`--port` 与 `--confirm-demo` 均为必填。脚本读取当前检出的 `scripts/.demo-local/processes.json`，核对登记的后端 PID、进程创建时间、本检出的服务宿主启动参数和回环 TCP 连接归属。状态文件缺失、端口不匹配或进程身份无法确认时会退出。演示库位于 `scripts/.demo-local/demo.sqlite`。

## 4. 重跑与保留演示库

- 接单接口在同一 `local-demo` 来源内按外部编号重放回执。脚本核对已有工单的历史，跳过已完成的配方，并从下一个动作续跑。
- 汇总分别统计新建并完成、补跑完成、已完成跳过和失败。任何配方失败都会返回退出码 `1`，相应工单可能已经提交或走完部分动作。处理错误后用同一演示库和凭据重跑。提交内容冲突、历史与配方不符或业务窗口已过期时，需检查对应工单。
- 展示结束后执行 `& .\scripts\答辩停止.ps1`，演示库会保留。如需从空库重新开始，先停止本检出的演示实例，再把 `scripts/.demo-local/demo.sqlite` 改名归档，然后重新启动并造数。

## 5. 月报口径

用值班角色查询 `GET /api/v1/staff/monthly-report?month=2026-11`。月份按实际流转事件的北京时间计算，跨月运行时请查询实际运行月份。

这批工单在同月跑完且库里仅有本批数据时，月报记录提交 13 条、受理 10 条、完成 5 条、发布 5 个轮次、有效评价 3 条、补办申请 1 条。速度、效果、态度均分各约为 4.67，评价覆盖率为 60%。月报以当轮发布反馈计完成，三条已评价工单均已确认解决。
