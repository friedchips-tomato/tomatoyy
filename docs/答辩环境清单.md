## 2. 后端 4 个必填环境变量

出处：`changdi-intake/server/src/main.js:10-17`、`changdi-intake/server/README.md:9-29`、`changdi-intake/server/src/auth.js`。

| 变量 | 是否必填 | 缺省会怎样 | 说明 |
| --- | --- | --- | --- |
| `CHANGDI_RECEIPT_KEY` | **必填** | 启动直接失败 | 必须是 **43 位 base64url**（32 字节）；`server/src/main.js:11-13` 校验正则与往返编码。用途是给回执与私密查询凭证签名 |
| `CHANGDI_INTEGRATIONS_JSON` | **必填** | 启动直接失败 | 接单方（合作方）目录，**必须是非空数组**：`server/src/auth.js:12-15` 里只有这一项校验了 `length`，为空即 `Invalid identity configuration` |
| `CHANGDI_STAFF_JSON` | **必填**（否则没有工作人员账号） | 数组为空时服务能起，但没有任何工单接口可用 | 工作人员目录，每项 `{ id, role, token }`，`role` 只能是 `duty` / `supervisor` / `handler`（`server/src/auth.js:5`）；非 `duty` 必须带 `department`（`server/src/auth.js:37-39`） |
| `CHANGDI_MERCHANTS_JSON` | **必填**（否则没有商户账号） | 数组为空时服务能起，但商户接口全 401/403 | 商户成员目录，每项 `{ id, merchantId, token, permissions }`，`permissions` 取值 `readCases` / `submitCases` / `collaborate`（`server/src/auth.js:6`） |

其他可选项（不配就是默认行为，答辩不需要动）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `CHANGDI_PORT` | `3400` | 端口（`server/src/main.js:20`） |
| `CHANGDI_WECHAT_CODE_ENABLED` | `0`（关闭） | 微信小程序码开关，关闭时回执只有三个字段（`server/src/main.js:24-32`） |
| `CHANGDI_WECHAT_LOGIN_ENABLED` | `0`（关闭） | 工作人员 / 商户微信登录开关（`server/src/main.js:26-27`） |
| `CHANGDI_EVALUATION_SECONDS` / `CHANGDI_REOPEN_SECONDS` | 7 天 / 30 天 | 评价窗与补办窗（`server/src/main.js:22-23`） |
| `CHANGDI_PARKING_RATE_LIMIT` | `{"windowSeconds":600,"limit":60}` | 停车接口限流（`server/src/main.js:53-54`） |

### 2.1 现成可抄的值（合成演示值）

`CHANGDI_RECEIPT_KEY`（43 位）：

```
<RECEIPT_KEY>
```

`CHANGDI_INTEGRATIONS_JSON`：

```json
[{"source":"local-demo","token":"<INTEGRATION_TOKEN>"}]
```

`CHANGDI_STAFF_JSON`（三个角色，与 `server/src/auth.js:5` 的角色定义一致；`desk` 是值班，`handler-a` 是承办，`lead-a` 是主管，`street` 为部门）：

```json
[{"id":"desk","role":"duty","token":"<DUTY_TOKEN>"},{"id":"handler-a","role":"handler","department":"street","token":"<HANDLER_TOKEN>"},{"id":"lead-a","role":"supervisor","department":"street","token":"<SUPERVISOR_TOKEN>"}]
```

`CHANGDI_MERCHANTS_JSON`（两家商户，权限对齐 `server/src/auth.js:6`）：

```json
[{"id":"shop-a-member","merchantId":"shop-a","token":"<MERCHANT_TOKEN_A>","permissions":["readCases","submitCases","collaborate"]},{"id":"shop-b-member","merchantId":"shop-b","token":"<MERCHANT_TOKEN_B>","permissions":["readCases","submitCases","collaborate"]}]
```

**令牌规则**（`server/src/auth.js:9`）：每枚令牌 32–256 位，只允许 `A-Za-z0-9_-`；同一枚令牌不能同时出现在接单方 / 工作人员 / 商户三处，
重复即启动失败 `Duplicate credential`（`server/src/auth.js:25`）。上面 6 枚令牌互不相同，可直接用。

### 2.2 换成「每次随机生成」的写法

仓库 README 给的是随机生成版（`server/README.md:10-29`），适合正式演示库：

```powershell
function New-LocalToken { node -p "require('node:crypto').randomBytes(32).toString('base64url')" }
$env:CHANGDI_RECEIPT_KEY = New-LocalToken
$env:CHANGDI_INTAKE_DEMO_TOKEN = New-LocalToken
$env:CHANGDI_INTEGRATIONS_JSON = ConvertTo-Json -Compress -InputObject @(
    @{ source = 'local-demo'; token = $env:CHANGDI_INTAKE_DEMO_TOKEN }
)
$env:CHANGDI_STAFF_JSON = ConvertTo-Json -Compress -InputObject @(
    @{ id = 'desk'; role = 'duty'; token = (New-LocalToken) },
    @{ id = 'handler-a'; role = 'handler'; department = 'street'; token = (New-LocalToken) },
    @{ id = 'lead-a'; role = 'supervisor'; department = 'street'; token = (New-LocalToken) }
)
$env:CHANGDI_MERCHANT_DEMO_A = New-LocalToken
$env:CHANGDI_MERCHANT_DEMO_B = New-LocalToken
$env:CHANGDI_MERCHANTS_JSON = ConvertTo-Json -Compress -Depth 4 -InputObject @(
    @{ id = 'shop-a-member'; merchantId = 'shop-a'; token = $env:CHANGDI_MERCHANT_DEMO_A
       permissions = @('readCases', 'submitCases', 'collaborate') },
    @{ id = 'shop-b-member'; merchantId = 'shop-b'; token = $env:CHANGDI_MERCHANT_DEMO_B
       permissions = @('readCases', 'submitCases', 'collaborate') }
)
npm.cmd start
```

> **用随机版就要记住 key**：随机 key 与 `.local/intake.sqlite` 一一绑定，重启必须用同一个 key，
> 否则报 `Receipt key does not match database`（`server/src/store.js:70`）。要么记下来，要么每次演示前删库重来。

## 4. 健康检查

一条 curl 确认后端活着（匿名公开接口，只读、不消耗建单额度）：

```powershell
curl.exe -s -o NUL -w "backend HTTP %{http_code}`n" http://127.0.0.1:3400/api/v1/public/parking/lots
```

实测返回 `backend HTTP 200`（`GET /api/v1/public/parking/lots`，见 `server/README.md:149`）。
这条接口是只读目录接口，即使停车运行时数据缺失也会返回 200 并在 `note` 里写明降级原因，
所以它测的是**进程与路由是否活着**，不是数据是否可用（`server/README.md:153`）。

备选两条（都无需凭据）：

```powershell
# 1) 不带令牌打管理接口：返回 401 说明路由活着、鉴权生效
curl.exe -s -o NUL -w "staff HTTP %{http_code}`n" http://127.0.0.1:3400/api/v1/staff/me
# 2) 公开查询码查询：返回 404 说明路由活着
curl.exe -s -o NUL -w "query HTTP %{http_code}`n" http://127.0.0.1:3400/api/v1/public/cases/AAAAAAAAAAAAAAAAAAAAAAAA
```

接入层与静态页：

```powershell
curl.exe -s -o NUL -w "bridge HTTP %{http_code}`n" http://127.0.0.1:8932/
curl.exe -s -o NUL -w "h5 HTTP %{http_code}`n" http://127.0.0.1:8931/prototype-paper/
```

## 5. 常见报错与解法

| 现场看到的现象 | 真实原因（出处） | 解法 |
| --- | --- | --- |
| 终端只打印 `changdi-intake: startup failed. Check local configuration, data path and receipt key.`，进程退出码 1 | `server/src/main.js:66-69` 把所有启动期异常都吞成这一句通用提示。真实异常见下面几行 | 按第 5.1 节跑两条诊断脚本定位 |
| 诊断脚本报 `身份配置错误: Invalid identity configuration` | `server/src/auth.js:14`。`CHANGDI_INTEGRATIONS_JSON` 是空数组 `[]`（默认）或不是数组；`CHANGDI_STAFF_JSON` / `CHANGDI_MERCHANTS_JSON` 不是数组 | 三个 JSON 都给第 2.1 节的现成值（接单方必须非空） |
| 诊断脚本报 `回执密钥不合法` | `server/src/main.js:11-13`：必须是 43 位 base64url | 直接用第 2.1 节的 `<RECEIPT_KEY>` |
| 诊断脚本报 `Receipt key does not match database` | `server/src/store.js:70`：库是别的 key 建的 | 删掉演示库重建：`Remove-Item .\changdi-intake\server\.local\intake.sqlite`；或找回原 key。**换 key 重启必失败**（`server/README.md:32`） |
| `changdi-intake: listen failed (EADDRINUSE)`，退出码 1 | `server/src/main.js:57-61`：端口被占 | `Get-NetTCPConnection -State Listen -LocalPort 3400` 查出占用进程；或改 `CHANGDI_PORT`（改了端口要同步小程序基址 `changdi-intake/miniprogram/config.js:4`） |
| 公开建单返回 `429 too_many_requests`（带 `Retry-After`） | 公开建单限流**每 600 秒 10 次新建**（`server/src/public-rate-limit.js:3-4`）。重放同一个 `clientRequestId` 不消耗额度 | 演示只建 1–2 单即可；超了就等窗口或换 `clientRequestId` 之外的内容另建。**该阈值目前无环境变量可调** |
| 停车接口返回 `429 too_many_requests` | 停车三接口限流**每 600 秒 60 次**（`server/src/parking/limiter.js:3`；`server/README.md:145`） | 演示期轮询别太密；需要放宽就设 `CHANGDI_PARKING_RATE_LIMIT='{"windowSeconds":600,"limit":600}'` |
| 任何管理接口返回 `401 {"error":"unauthorized"}` | 没带 `Authorization: Bearer <令牌>`，或令牌不是本会话配置的那枚 | 用第 2.1 节对应角色的令牌；注意令牌不通用 |
| 返回 `403 {"error":"forbidden"}` | 角色不匹配：接单凭据不能调管理接口，工作人员不能调商户接口（`server/src/auth.js:93-95`） | 换正确角色的令牌 |
| 公开提交返回 `409 submission_conflict` | 同一个 `clientRequestId` 换了内容（`server/README.md:123-125`） | 重试要用**原单号 + 原内容** |
| 回执里没有小程序码 / 微信登录 404 | 微信小程序码与微信登录**默认关闭**：`CHANGDI_WECHAT_CODE_ENABLED`、`CHANGDI_WECHAT_LOGIN_ENABLED` 默认 `0`（`server/src/main.js:24-27`） | 演示就用回执的三个字段（`caseNumber` / `publicLookupCode` / `privateLookupToken`），不要承诺小程序码 |
| 找不到 `python3` / 退出码 49 | 本机 `python3` 是 WindowsApps 存根 | 用 `python -m http.server 8931 --bind 127.0.0.1` |
| 工单数据不见了 | 数据库落在 `changdi-intake/server/.local/intake.sqlite`（`server/src/main.js:38-41`），该目录被 git 忽略 | 演示前删库即可清空；重启不清数据（`server/README.md:32`） |
| 停车数据看着像真数据 | 停车接口当前是**合成示范数据**，`source` 为 `synthetic`，不是真实车场余位（`server/README.md:145`） | 页面与讲稿必须标注「模拟」 |

### 5.1 两条诊断脚本（启动失败时先跑这两条）

在 `changdi-intake/server` 目录、已设好环境变量的同一个 PowerShell 里执行：

```powershell
# 身份目录诊断：会打印真实的 auth 异常
node --input-type=module -e "import {createAuth} from './src/auth.js'; const p=v=>JSON.parse(process.env[v]??'[]'); try{createAuth(p('CHANGDI_INTEGRATIONS_JSON'),p('CHANGDI_STAFF_JSON'),p('CHANGDI_MERCHANTS_JSON'),{});console.log('身份配置 OK')}catch(e){console.error('身份配置错误:',e.message)}"

# 回执密钥诊断
node -e "const k=process.env.CHANGDI_RECEIPT_KEY??'';console.log(/^[A-Za-z0-9_-]{43}$/.test(k)&&Buffer.from(k,'base64url').toString('base64url')===k?'回执密钥 OK（43 位 base64url）':'回执密钥不合法')"
```

> 备注：`server/src/main.js:66` 的 `catch` 会把具体异常吞掉，所以上面两条脚本是现场唯一能拿到真实原因的办法；
> 两脚本都是只读调用，不写库、不改代码。

## 6. 一张工单的演示顺序（9 步）

来源：`changdi-intake/docs/local-acceptance.md:32-49`（角色顺序、页面动作与预期现象均按该手册）。
贯穿主线用**同一个 `caseNumber`**；下面是每一步对应的接口与方法，便于在浏览器演示之外用 curl 复现。

| 步 | 角色 | 怎么演示 | 对应接口与方法 | 应观察到的现象 |
| --- | --- | --- | --- | --- |
| 1 | 合作方代匿名提交人 | 发送一次申报，再原样重试 | `POST /api/v1/integrations/intake/cases`（`Authorization: Bearer <接入令牌>`，multipart：`payload` 一个 JSON 文本 part + 可选 `photos`） | 首次 `201`，原样重试 `200`，三字段回执一致（`caseNumber` / `publicLookupCode` / `privateLookupToken`），待受理只增加一张 |
| 2 | 匿名提交人 / 普通访客 | 「游客与居民」页手输公开码查询 | `GET /api/v1/public/cases/{publicLookupCode}`（匿名，24 位公开码） | 只见工单编号、当前状态与可公开时间节点，初始 `submitted`；不返回联系方式、说明与照片 |
| 3 | 值班 `desk` → 原提交人 → 值班 | 值班点「要求补材料」；原提交人核验后填「补充材料」并可选补件照片 | 值班：`POST /api/v1/staff/cases/{caseNumber}/actions`，`{"action":"request_supplement","expectedVersion":N,"reason":"请补充发生时段"}`；本人核验：`POST /api/v1/owner/verify`，`{"publicLookupCode":"…","privateLookupToken":"…"}` → 拿 `ownerSessionToken`；本人详情：`GET /api/v1/owner/cases/{caseNumber}`；本人补件：`POST /api/v1/owner/cases/{caseNumber}/actions`，`{"action":"submit_supplement","expectedVersion":N,"summary":"…"}`（带图时同一路径 multipart） | 工单先移出待受理；本人可见补件要求与提出时间；补件后原编号原轮次回到待受理；公开页只有状态与时间节点 |

| 6 | 主管 `lead-a` → 店 A → 主管 | 主管「退回补充」写原因；店 A 看原因重交；主管「通过协办」 | `POST /api/v1/staff/cases/{caseNumber}/collaborations/{taskId}/actions`，`{"action":"return","expectedVersion":N,"reason":"…"}` → 店 A 重交 → `{"action":"approve","expectedVersion":N}` | 只更新协办版本；主单保持步骤 4 的已分派状态与版本 |

| 8 | 主管 `lead-a` | 「发布图片反馈」：填文字 + 选 1–3 张**另存**的脱敏 PNG，勾人工脱敏确认再发布；也可走「发布文字反馈」 | `POST /api/v1/staff/cases/{caseNumber}/actions`，`{"action":"publish","expectedVersion":N,"summary":"…","derivativesReviewed":true}`（带图 multipart，`photos` 为脱敏 PNG，8 位 RGB、非隔行、边长 ≤2048、≤5 MiB） | 图片走独立发布、不能引用送审原图（引用原图返回 `409 feedback_original_not_allowed`）；未确认脱敏会被拒；成功后为待评价 |
| 9 | 原匿名提交人 → 主管 | 本人核验后评分 + 点「确认解决」；再申请补办；主管在补办队列点「通过补办」并重新分派 | 评价与解决：`POST /api/v1/owner/cases/{caseNumber}/actions`，`{"action":"evaluate","speed":5,"effectiveness":5,"attitude":5}` / `{"action":"confirm_resolved"}` / `{"action":"request_reopen","reason":"…"}`；主管补办：`POST /api/v1/staff/cases/{caseNumber}/actions`，`{"action":"approve_reopen","expectedVersion":N,"assignee":"handler-a","dueAt":"…","nextStatus":"assigned"}` | 评分后仍待评价，确认解决后已办结；批准补办后原编号进入第 2 轮回到已分派；第 1 轮反馈与评分保留 |

### 6.1 三个必须记住的坑

1. **每个写操作都要带 `expectedVersion`**（来自最近一次详情响应），版本过期返回 `409 stale_version`，此时先刷新详情再操作。
2. **本人核验只对一张单有效**，授权 30 分钟失效，失效返回 `401 owner_authorization_required`（`server/README.md:237-240`）。
3. **微信相关一律默认关闭**，演示不要承诺小程序码、微信登录、扫码落页。
