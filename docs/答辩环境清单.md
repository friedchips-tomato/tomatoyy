# 答辩环境清单（11-28 初期答辩现场用）

> 用途：现场演示前照着本清单，用仓库自带的 T16 启停脚本拉起「接诉即办后端 + 导览 H5 + 运营台 + 接入层」；拉不起来时按第 7 节兜底。
> 默认入口：启动 `scripts\答辩启动.ps1`，状态 `scripts\答辩启动.ps1 -Status`，停止 `scripts\答辩停止.ps1`。
> 依据：仓库 `changdi-intake/` 与 `scripts/` 源码；路径、端口、变量名后附出处（见第 9 节）。
> 实测：第 8 节保留 2026-11-23 在本机（Windows 11 / PowerShell 5.1 / Node v22.17.0）跑通的历史输出时点，并补充同日用备用端口 13400/18931/18932 做的启停与四入口复核。
> 合规声明：本文不写任何固定凭据。现场使用的合成凭据由第 2.2 节命令在本机生成，保存在 Git 忽略目录，不打印、不入库。

## 0. 三十秒版（现场只记这一段）

前提：在仓库根目录、Node.js ≥ 22.17、PowerShell 5.1；首次先执行一次第 2.2 节生成合成凭据（只需一次）。

```powershell
cd D:\乐游蓬江AI智慧导览小程序\tomatoyy

# 启动：优先用备用端口组合（默认端口可能被外部进程占用）
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\答辩启动.ps1 -BackendPort 13400 -StaticPort 18931 -BridgePort 18932

# 状态：读取上次成功启动登记的端口，无需再传端口参数
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\答辩启动.ps1 -Status

# 停止：只停本检出登记并核实过身份的进程
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\答辩停止.ps1
```

健康检查（后端匿名只读接口）：

```powershell
curl.exe -s -o NUL -w "backend HTTP %{http_code}`n" http://127.0.0.1:13400/api/v1/public/parking/lots
```

出 `backend HTTP 200` 即可开讲。四个入口：

| 页面 | 地址 |
| --- | --- |
| 导览 H5 游客端（手机竖屏） | <http://127.0.0.1:18931/prototype-paper/> |
| 值班运营台 | <http://127.0.0.1:18931/prototype-paper/ops.html> |
| 点位卡配图对比 | <http://127.0.0.1:18931/prototype-paper/pic-compare.html> |
| 接诉闭环版 H5（经接入层，提交直达后端） | <http://127.0.0.1:18932/> |

三个端口：

| 服务 | 本清单备用端口 | 默认端口 | 说明 |
| --- | ---: | ---: | --- |
| 接诉即办后端 | **13400** | 3400 | 启动器参数 `-BackendPort`（`scripts/答辩启动.ps1:22`） |
| 原型静态站（H5 / 运营台 / 配图对比） | **18931** | 8931 | 启动器参数 `-StaticPort`（`scripts/答辩启动.ps1:23`） |
| 导览接入层 guide-bridge | **18932** | 8932 | 启动器参数 `-BridgePort`（`scripts/答辩启动.ps1:24`） |

> **默认端口 3400 / 8931 / 8932 上如果已有监听，那是本检出之外的外部进程，不要擅自停止。**
> 启动器启动前会打印占用端口的 PID；请直接改用上面的备用端口组合，而不是结束别人的进程。
> 只有本检出通过启动器拉起、并在 `scripts\.demo-local\processes.json` 登记过的进程，才用 `答辩停止.ps1` 停止。

启动器只让三个服务监听 `127.0.0.1`（`scripts/答辩启动.ps1:451`；接入层自身入口也只监听回环，`changdi-intake/guide-bridge/server.js:104`），不监听非回环地址。三个服务都由启动器托管，不需要另开终端跑静态服务器或 Node。

## 2. 本机合成凭据

启动器从当前进程环境或 `scripts\.demo-local\credentials.json` 读取凭据；当前进程的非空值优先（`scripts/答辩启动.ps1:311-337`）。凭据文件必须是**平面 JSON 对象**：键只能用启动器允许的环境变量名，值必须都是字符串，`*_JSON` 项的值是 JSON 字符串；出现未知键或非字符串值会拒绝启动。

### 2.1 必填与可选凭据

| 键 | 启动器是否必填 | 结构 / 校验 | 出处 |
| --- | --- | --- | --- |
| `CHANGDI_RECEIPT_KEY` | **必填** | 43 位 base64url（32 字节），且往返编码一致 | `scripts/答辩启动.ps1:330-332`；`changdi-intake/server/src/main.js:75-78`；`server/src/store.js:66-70` |
| `CHANGDI_INTEGRATIONS_JSON` | **必填** | 非空 JSON 数组，每项 `{source, token}`；`source` 为 1–64 位 `[A-Za-z0-9_-]`，`token` 为 32–256 位 `[A-Za-z0-9_-]` | `server/src/auth.js:12-15,30-33` |
| `GUIDE_INTAKE_TOKEN` | **必填** | 32–256 位 `[A-Za-z0-9_-]`；必须等于某个接单方 token，接入层才能代 H5 提交 | `scripts/答辩启动.ps1:330-332,443`；`guide-bridge/server.js:12-17,34` |
| `CHANGDI_STAFF_JSON` | 可选（不配则没有工作人员账号） | JSON 数组，每项 `{id, role, token, department?}`；`role` 只能是 `duty` / `supervisor` / `handler`；非 `duty` 必须带 `department` | `server/src/auth.js:5,34-49` |
| `CHANGDI_MERCHANTS_JSON` | 可选（不配则没有商户账号） | JSON 数组，每项 `{id, merchantId, token, permissions[]}`；`permissions` 取值 `readCases` / `submitCases` / `collaborate` | `server/src/auth.js:6,50-61` |
| `CHANGDI_TOURISM_JSON` | 可选（本演示不启用） | JSON 对象 `{sources, coverage}` | `server/src/main.js:85`；`server/src/server.js:50-54` |
| `GUIDE_METRICS_TOKEN` | 可选 | 32–256 位 `[A-Za-z0-9_-]`，且必须与 `GUIDE_INTAKE_TOKEN` 不同 | `guide-bridge/server.js:16`；`scripts/答辩启动.ps1:444` |

规则（`server/src/auth.js:9,21-28`）：每枚令牌 32–256 位，只允许 `A-Za-z0-9_-`；同一枚令牌不能同时出现在接单方 / 工作人员 / 商户三处，重复即启动失败 `Duplicate credential`。

> 启动器只把上表这些键传给子进程（`scripts/答辩启动.ps1:40-42,516-522`）。`CHANGDI_PORT`、`CHANGDI_EVALUATION_SECONDS`、`CHANGDI_REOPEN_SECONDS`、`CHANGDI_PARKING_RATE_LIMIT`、`CHANGDI_WECHAT_*` 只对直接运行 `changdi-intake/server/src/main.js` 生效；走启动器时一律用服务默认值（微信码与微信登录关闭、公开建单 600 秒 10 次、停车接口 600 秒 60 次）。

### 2.2 首次配置（PS5.1 可照抄，只做一次）

在**仓库根目录**执行下面整段。它生成 7 个互相独立的本机随机值（回执密钥 1 个 + 令牌 6 个），保存到 Git 忽略的 `scripts\.demo-local\credentials.json`；不打印任何值；文件已存在时直接复用、不覆盖。

```powershell
$credDir = Join-Path (Get-Location) 'scripts\.demo-local'
$credFile = Join-Path $credDir 'credentials.json'
if (Test-Path -LiteralPath $credFile) {
    Write-Host "复用已有凭据文件：$credFile"
} else {
    New-Item -ItemType Directory -Force -Path $credDir | Out-Null
    function New-Token { node -p "require('node:crypto').randomBytes(32).toString('base64url')" }
    $receipt = New-Token
    $intake  = New-Token
    $desk    = New-Token
    $handler = New-Token
    $lead    = New-Token
    $shopA   = New-Token
    $shopB   = New-Token
    $config = [ordered]@{
        CHANGDI_RECEIPT_KEY       = $receipt
        CHANGDI_INTEGRATIONS_JSON = ConvertTo-Json -Compress -InputObject @(
            @{ source = 'local-demo'; token = $intake })
        CHANGDI_STAFF_JSON        = ConvertTo-Json -Compress -InputObject @(
            @{ id = 'desk'; role = 'duty'; token = $desk },
            @{ id = 'handler-a'; role = 'handler'; department = 'street'; token = $handler },
            @{ id = 'lead-a'; role = 'supervisor'; department = 'street'; token = $lead })
        CHANGDI_MERCHANTS_JSON    = ConvertTo-Json -Compress -Depth 4 -InputObject @(
            @{ id = 'shop-a-member'; merchantId = 'shop-a'; token = $shopA
               permissions = @('readCases', 'submitCases', 'collaborate') },
            @{ id = 'shop-b-member'; merchantId = 'shop-b'; token = $shopB
               permissions = @('readCases', 'submitCases', 'collaborate') })
        GUIDE_INTAKE_TOKEN        = $intake
    }
    $json = ConvertTo-Json -InputObject $config -Depth 5
    [IO.File]::WriteAllText($credFile, $json, (New-Object System.Text.UTF8Encoding($false)))
    Write-Host "已生成本机合成凭据：$credFile"
}
```

说明：

- 键名与 JSON 结构按启动器的允许名单（`scripts/答辩启动.ps1:312-313`）和身份目录校验（`server/src/auth.js:12-61`）构造：`source` / `id` / `merchantId` 都是 `[A-Za-z0-9_-]`，令牌都是 43 位 base64url，`role` 与 `permissions` 都在枚举内。
- `GUIDE_INTAKE_TOKEN` 故意复用接单方那枚令牌：接入层要拿它去调 `POST /api/v1/integrations/intake/cases`（`guide-bridge/server.js:34`），所以它必须同时是合法的接单凭据。
- 生成后用 PowerShell 再执行一次整段，只会输出「复用已有凭据文件」，不会覆盖；第二次及以后启动也不需要再配任何环境变量。
- 该文件是明文凭据，只留在本机；不要复制进仓库、不要发到公网。确需另存一份时，用启动器的 `-CredentialsFile <路径>` 指定，不要手工改键名或 JSON 结构。

### 2.3 凭据与演示库的绑定（库始终保留）

启动器把演示库固定在 `scripts\.demo-local\demo.sqlite`（`scripts/答辩启动.ps1:180-183`；服务宿主同一路径）。回执密钥与这个演示库绑定：换掉 `CHANGDI_RECEIPT_KEY` 而继续用旧库，启动器会报 `演示库与 CHANGDI_RECEIPT_KEY 不匹配，已保留数据库。` 并保留数据库与所有侧车文件（`scripts/答辩启动.ps1:469-471`）。

因此现场只守一条：**凭据文件生成一次后就整份复用**。启动器始终保留演示库；换密钥时不重建数据库。若提示不匹配，恢复原来那份 `credentials.json`，不要重建库。

## 3. 启停、状态与端口

| 操作 | 命令 | 端口 | 出处 |
| --- | --- | --- | --- |
| 启动 | `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\答辩启动.ps1 -BackendPort 13400 -StaticPort 18931 -BridgePort 18932` | 13400 / 18931 / 18932 | `scripts/答辩启动.ps1:16-25,34,496-578` |
| 状态 | `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\答辩启动.ps1 -Status` | 读取上次登记的端口 | `scripts/答辩启动.ps1:596` |
| 停止 | `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\答辩停止.ps1` | 同上 | `scripts/答辩停止.ps1:7`；`答辩启动.ps1:597-616` |

补充说明：

- `-Status` 与 `-Stop` **不接受端口参数**；它们读取 `scripts\.demo-local\processes.json` 里上次成功启动登记的端口。停止成功后该登记文件会被移除。
- 没有登记实例时，`-Status` 会按默认端口 3400 / 8931 / 8932 检查。现场这些默认端口如果有外部监听，会显示 `监听冲突（PID …）`、退出码 1；这**不代表演示实例还在跑**，只说明默认端口被外部进程占着。
- 退出码（`scripts/答辩启动.ps1:12`）：`-Status` 返回 0 表示三个服务都就绪，2 表示三个都停止，1 表示异常。
- 重复执行启动且现有实例健康时，启动器会沿用现有实例（`scripts/答辩启动.ps1:628`）；如果显式传了不同端口，会要求先停止（`:626`）。
- 三个端口必须互不相同（`scripts/答辩启动.ps1:617-619`）。`-KeepDb` 是兼容参数，演示库始终保留，不需要传。
- 停止后确认备用端口空闲（无输出即已释放）：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 13400,18931,18932 -ErrorAction SilentlyContinue
```

> 上线前预检（T17）与种子数据（T18）仍在另行验收，本文不写其调用语法；现场以本节的启动 / 状态 / 停止脚本为准。

## 4. 健康检查

启动器在启动时已经对三个服务各做一次 HTTP 健康检查，并打印 `HTTP 200（PID …）`。现场想手工再确认，用下面三条（都只读、不需要凭据）：

```powershell
curl.exe -s -o NUL -w "backend HTTP %{http_code}`n" http://127.0.0.1:13400/api/v1/public/parking/lots
curl.exe -s -o NUL -w "static  HTTP %{http_code}`n" http://127.0.0.1:18931/prototype-paper/
curl.exe -s -o NUL -w "bridge  HTTP %{http_code}`n" http://127.0.0.1:18932/
```

后端那条是公开停车目录接口，只读、不消耗建单额度；即使停车运行时数据缺失也会返回 200 并在 `note` 里写明降级原因，所以它测的是**进程与路由是否活着**，不是数据是否可用（`server/README.md:149-153`）。

备选两条（都无需凭据）：

```powershell
# 1) 不带令牌打管理接口：返回 401 说明路由活着、鉴权生效
curl.exe -s -o NUL -w "staff HTTP %{http_code}`n" http://127.0.0.1:13400/api/v1/staff/me
# 2) 公开查询码查询：返回 404 说明路由活着
curl.exe -s -o NUL -w "query HTTP %{http_code}`n" http://127.0.0.1:13400/api/v1/public/cases/AAAAAAAAAAAAAAAAAAAAAAAA
```

静态站只服务白名单文件；`/`、`/README.md`、`/package.json` 以及 `prototype-paper/` 之外的文件都会返回 404（`scripts/答辩启动.ps1:402-437`）。

## 5. 常见报错与解法

启动器的失败提示是固定文案，不会回显凭据原文；先按提示对号入座。

| 现场看到的现象 | 真实原因（出处） | 解法 |
| --- | --- | --- |
| 启动前打印 `有端口被占用，请释放相应端口或指定三个可用端口。` | 目标端口已被其他进程监听（`scripts/答辩启动.ps1:498-499`） | 改用备用端口 `-BackendPort 13400 -StaticPort 18931 -BridgePort 18932`；**不要擅自停止外部进程** |
| 启动中打印 `<服务> <端口>  监听冲突（PID …）` | 同上，启动器在健康检查时发现监听者不是自己（`scripts/答辩启动.ps1:289,547`） | 同上；先确认该 PID 是不是本检出登记的进程 |
| 子进程报 `接诉即办后端 启动失败。监听时发现端口被占用。` | 子进程监听时 `EADDRINUSE`（`scripts/答辩启动.ps1:450`；退出码 27） | 同上 |
| `接诉即办后端 启动失败。CHANGDI_RECEIPT_KEY 格式无效。` | 回执密钥不是 43 位 base64url（`scripts/答辩启动.ps1:468`；`server/src/main.js:75-78`） | 用第 2.2 节整段重新生成，不要手工改 |
| `接诉即办后端 启动失败。CHANGDI_INTEGRATIONS_JSON 必须为 JSON 数组。`（STAFF / MERCHANTS 同理） | 凭据文件里对应的 `*_JSON` 不是 JSON 数组字符串（`scripts/答辩启动.ps1:477-479`；`server/src/auth.js:12-15`） | 用第 2.2 节生成的文件；接单方必须非空 |
| `接诉即办后端 启动失败。CHANGDI_TOURISM_JSON 必须为 JSON 对象。` | 该可选键不是对象（`scripts/答辩启动.ps1:480`） | 本演示不配这个键即可 |
| `接诉即办后端 启动失败。演示库与 CHANGDI_RECEIPT_KEY 不匹配，已保留数据库。` | 换过回执密钥但还在用旧 `demo.sqlite`（`scripts/答辩启动.ps1:471`；`server/src/store.js:70`） | 恢复生成该库时用的那份 `credentials.json`；**保留数据库，不要重建** |
| `接诉即办后端 启动失败。演示库版本不兼容，已保留数据库。` | 演示库 schema 版本与当前检出不一致（`scripts/答辩启动.ps1:470`） | 换回创建该库的检出，或由现场负责人另行处理运行目录 |
| `导览接入层 启动失败。GUIDE_INTAKE_TOKEN 格式无效。` | 接入令牌不是 32–256 位 base64url（`scripts/答辩启动.ps1:472`；`guide-bridge/server.js:15`） | 用第 2.2 节整段生成 |
| `导览接入层 启动失败。GUIDE_METRICS_TOKEN 格式无效或与接单凭据相同。` | 可选的指标令牌格式错，或与接单令牌重复（`scripts/答辩启动.ps1:473`；`guide-bridge/server.js:16`） | 不配这个键，或另生成一个不同值 |
| `缺少合成凭据配置 CHANGDI_RECEIPT_KEY。`（或 `CHANGDI_INTEGRATIONS_JSON` / `GUIDE_INTAKE_TOKEN`） | 凭据文件和当前进程环境里都没有必填项（`scripts/答辩启动.ps1:330-332`） | 先执行第 2.2 节 |
| `凭据文件不可读取，或不是由支持的环境变量名和字符串值组成的 JSON 对象。` | 文件被改坏、含未知键或非字符串值（`scripts/答辩启动.ps1:315-324`） | 只用第 2.2 节生成的文件，不要手工加键 |
| `三个服务必须使用不同端口。` | 三个端口参数有重复（`scripts/答辩启动.ps1:617-619`） | 用 13400 / 18931 / 18932 |
| `已有演示实例异常，请先运行答辩停止.ps1。` / `现有实例使用不同端口，请先运行答辩停止.ps1。` | 已登记的实例不健康，或显式换了端口（`scripts/答辩启动.ps1:620-630`） | 先运行 `答辩停止.ps1`，再启动 |
| `<服务> <端口> 健康检查超时。…` | 子进程 15 秒内没有返回 HTTP 200（`scripts/答辩启动.ps1:542-550`） | 查 Node 版本（≥22.17）、端口占用与进程是否还活着 |
| `启动器无法完成操作（…）。请检查本机目录权限、Node.js 和端口状态。` | 非预期异常；启动器只输出固定诊断（`scripts/答辩启动.ps1:649-655`） | 检查仓库目录权限、`node --version`、端口状态；必要时按第 5.1 节取原始异常 |

### 5.1 需要原始异常时（只读诊断）

启动器把失败归成固定文案；要看原始异常，先把本机凭据文件导入**当前 PowerShell 进程**（不打印任何值），再跑两条只读脚本。仍在仓库根目录执行：

```powershell
$c = Get-Content -LiteralPath .\scripts\.demo-local\credentials.json -Raw -Encoding UTF8 | ConvertFrom-Json

# 身份目录诊断：打印真实的 auth 异常（不含令牌值）
node --input-type=module -e "import {createAuth} from './changdi-intake/server/src/auth.js'; const p=v=>JSON.parse(process.env[v]??'[]'); try{createAuth(p('CHANGDI_INTEGRATIONS_JSON'),p('CHANGDI_STAFF_JSON'),p('CHANGDI_MERCHANTS_JSON'),{});console.log('身份配置 OK')}catch(e){console.error('身份配置错误:',e.message)}"

node -e "const k=process.env.CHANGDI_RECEIPT_KEY??'';console.log(/^[A-Za-z0-9_-]{43}$/.test(k)&&Buffer.from(k,'base64url').toString('base64url')===k?'回执密钥 OK（43 位 base64url）':'回执密钥不合法')"
```

## 6. 一张工单的演示顺序（9 步）

来源：`changdi-intake/docs/local-acceptance.md:32-49`（角色顺序、页面动作与预期现象均按该手册）。在 18931 的运营台与 18932 的接诉闭环 H5 上操作；四个入口见第 0 节。
贯穿主线用**同一个 `caseNumber`**；下面是每一步对应的接口与方法，便于在浏览器演示之外用 curl 复现。

| 步 | 角色 | 怎么演示 | 对应接口与方法 | 应观察到的现象 |
| --- | --- | --- | --- | --- |
| 1 | 合作方代匿名提交人 | 发送一次申报，再原样重试 | `POST /api/v1/integrations/intake/cases`（`Authorization: Bearer <接单令牌>`，multipart：`payload` 一个 JSON 文本 part + 可选 `photos`） | 首次 `201`，原样重试 `200`，三字段回执一致（`caseNumber` / `publicLookupCode` / `privateLookupToken`），待受理只增加一张 |
| 2 | 匿名提交人 / 普通访客 | 「游客与居民」页手输公开码查询 | `GET /api/v1/public/cases/{publicLookupCode}`（匿名，24 位公开码） | 只见工单编号、当前状态与可公开时间节点，初始 `submitted`；不返回联系方式、说明与照片 |
| 3 | 值班 `desk` → 原提交人 → 值班 | 值班点「要求补材料」；原提交人核验后填「补充材料」并可选补件照片 | 值班：`POST /api/v1/staff/cases/{caseNumber}/actions`，`{"action":"request_supplement","expectedVersion":N,"reason":"请补充发生时段"}`；本人核验：`POST /api/v1/owner/verify`，`{"publicLookupCode":"…","privateLookupToken":"…"}` → 拿 `ownerSessionToken`；本人详情：`GET /api/v1/owner/cases/{caseNumber}`；本人补件：`POST /api/v1/owner/cases/{caseNumber}/actions`，`{"action":"submit_supplement","expectedVersion":N,"summary":"…"}`（带图时同一路径 multipart） | 工单先移出待受理；本人可见补件要求与提出时间；补件后原编号原轮次回到待受理；公开页只有状态与时间节点 |
| 4 | 值班 `desk` | 刷新待受理 → 「受理」「分派」选 `handler-a` 与未来期限；详情「协办任务」→「派发协办」填 `shop-a` | 受理+分派：`POST /api/v1/staff/cases/{caseNumber}/actions`，`{"action":"accept"}` / `{"action":"assign","expectedVersion":N,"assignee":"handler-a","dueAt":"2026-11-23T18:00:00+08:00"}`；派发协办：`POST /api/v1/staff/cases/{caseNumber}/collaborations`，`{"expectedVersion":N,"merchantId":"shop-a","instructions":"…","dueAt":"…","location":"…"}` | 原单从已受理到已分派；协办任务出现新任务；派发使主单版本 +1，任务从自己初始版本开始 |
| 5 | 店 A `shop-a`、店 B `shop-b` | 各用自己令牌进商户工作台；店 A 打开获派任务提交协办说明（可选照片） | `GET /api/v1/merchant/me`；`GET /api/v1/merchant/cases`；`GET /api/v1/merchant/collaborations`；`GET /api/v1/merchant/collaborations/{taskId}`；提交：`POST /api/v1/merchant/collaborations/{taskId}/submissions` | 这张外部工单只在店 A 协办待办出现；详情只有任务说明、期限与必要地点，原单正文/联系方式/回执都不在其中；店 B 列表无任务，直接查任务返回 `404` |
| 6 | 主管 `lead-a` → 店 A → 主管 | 主管「退回补充」写原因；店 A 看原因重交；主管「通过协办」 | `POST /api/v1/staff/cases/{caseNumber}/collaborations/{taskId}/actions`，`{"action":"return","expectedVersion":N,"reason":"…"}` → 店 A 重交 → `{"action":"approve","expectedVersion":N}` | 只更新协办版本；主单保持步骤 4 的已分派状态与版本 |
| 7 | 承办 `handler-a` → 主管 `lead-a` | 承办接单 → 填说明 + 选 1–3 张合成图（≤5 MiB/张）送审；主管在待复核详情看「承办送审原图」 | 承办：`POST /api/v1/staff/cases/{caseNumber}/actions`，`{"action":"submit_result","expectedVersion":N,"summary":"现场已处理"}`（带图走 multipart，`photos` 可重复；纯文字分支要填 `photoOmissionReason`）；读图：`GET /api/v1/staff/cases/{caseNumber}/submission-photos/{submitVersion}/{position}` | 送审后状态 `awaiting_review`；主管与当前承办可按授权看原图，值班人员无此权限；公开页仍只展示脱敏进度 |
| 8 | 主管 `lead-a` | 「发布图片反馈」：填文字 + 选 1–3 张**另存**的脱敏 PNG，勾人工脱敏确认再发布；也可走「发布文字反馈」 | `POST /api/v1/staff/cases/{caseNumber}/actions`，`{"action":"publish","expectedVersion":N,"summary":"…","derivativesReviewed":true}`（带图 multipart，`photos` 为脱敏 PNG，8 位 RGB、非隔行、边长 ≤2048、≤5 MiB） | 图片走独立发布、不能引用送审原图（引用原图返回 `409 feedback_original_not_allowed`）；未确认脱敏会被拒；成功后为待评价 |
| 9 | 原匿名提交人 → 主管 | 本人核验后评分 + 点「确认解决」；再申请补办；主管在补办队列点「通过补办」并重新分派 | 评价与解决：`POST /api/v1/owner/cases/{caseNumber}/actions`，`{"action":"evaluate","speed":5,"effectiveness":5,"attitude":5}` / `{"action":"confirm_resolved"}` / `{"action":"request_reopen","reason":"…"}`；主管补办：`POST /api/v1/staff/cases/{caseNumber}/actions`，`{"action":"approve_reopen","expectedVersion":N,"assignee":"handler-a","dueAt":"…","nextStatus":"assigned"}` | 评分后仍待评价，确认解决后已办结；批准补办后原编号进入第 2 轮回到已分派；第 1 轮反馈与评分保留 |

### 6.1 三个必须记住的坑

1. **每个写操作都要带 `expectedVersion`**（来自最近一次详情响应），版本过期返回 `409 stale_version`，此时先刷新详情再操作。
2. **本人核验只对一张单有效**，授权 30 分钟失效，失效返回 `401 owner_authorization_required`（`server/README.md:237-240`）。
3. **微信相关一律默认关闭**，演示不要承诺小程序码、微信登录、扫码落页。
