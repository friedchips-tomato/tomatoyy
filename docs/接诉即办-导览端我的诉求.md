# 接诉即办 · 导览端「我的诉求」

游客在导览 H5（`prototype-paper/`）提交诉求后，刷新页面仍能在本机查看自己工单的真实办理进度，不必跳转小程序。

## 一、接入层新增端点

`changdi-intake/guide-bridge/server.js` 新增同源代理：

```
GET /bridge/my-cases/<公开查询码>
```

- 公开查询码必须是 24 位 `[A-Za-z0-9_-]`，形态不符（含多余路径段、编码后的分隔符）一律 404，不触达上游。
- 内部转发到上游 `GET /api/v1/public/cases/<code>`，状态码与响应体原样透传；上游 404 `case_not_found` → 接入层同样返回 404。
- 与既有 `/bridge/parking/*` 一致：`Cache-Control: no-store`；请求带 `Origin` 且与本页来源不符时 403；只允许单一 `my-cases` 模式，不是可拼路径的开放代理。
- 上游 5 秒超时或不可达时降级为 502 `{"error":"unavailable"}`，不把上游异常原文回传浏览器。

## 二、本机回执夹

`changdi-intake/guide-bridge/client.js`：

- 提交成功后把 `{caseNumber, publicLookupCode, submittedAt}` 写入 `localStorage` 的 `cd-bridge-receipts-v1`（数组，新条目在前）。
- **私密凭证 `privateLookupToken` 不写入任何持久化存储**，只留在内存与提交成功当下的回执页 DOM，刷新即消失。与小程序 `changdi-intake/miniprogram/pages/mine/index.js` 第 2 行注释同口径。
- 读取时逐条校验（`^CD-[0-9A-F]{32}$`、`^[A-Za-z0-9_-]{24}$`、`Date.parse` 可解析），不合法的条目直接丢弃，不原样渲染进 DOM。
- 写入时按 `publicLookupCode` 去重，最多保留 20 条，超限丢最旧的。
- localStorage 被禁用、配额满、JSON 损坏等异常一律静默降级为内存态，不白屏、不抛未捕获异常。

## 三、「我的诉求」面板

- 位置：导览 H5「服务 → 反馈」页内，作为反馈表单的同级区块，不进入表单，因此不影响接入层在 `document` 上 capture 阶段拦截提交（`stopImmediatePropagation`）的逻辑，也不与 `prototype-paper/app.js` 的演示反馈表单冲突。
- 展示：工单编号、提交时间、当前状态、进度节点，以及「重新查询」按钮（可单条重查）。
- 状态来自 `GET /bridge/my-cases/<publicLookupCode>` 的真实响应：查不到显示「查不到该工单」，查询失败显示「暂时查不到进度，请稍后再试」，离线显示「离线，状态未更新」，任何情况下都不展示臆造进度。
- 面板不出现私密凭证。
