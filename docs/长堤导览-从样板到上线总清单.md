# 江门长堤风貌街｜从像素样板到微信上线的总清单

这份清单用于派工、验收和判断还差什么。覆盖两份需求材料中的正式指标、上一版方案中的扩展项，以及最新确定的地图交互。与旧方案冲突时，以本清单的地图规则为准。它不代表已获得上线、付费出图或接入生产数据的授权。

## 1｜第一件可验收的东西：双骑楼竖屏样板

- [ ] **1.1 做证据底稿。** 负责人自行联网核地点、相邻路口、朝向和立面，记录页面、照片来源及可使用范围；不能证实的入口坐标、逐户门牌左右分配留空。旧示意钟楼不进入实景底稿。不要求用户逐栋找坐标。
- [ ] **1.2 出一段可替换的像素素材。** 环境底图、建筑彩色图、建筑轮廓、前景遮挡、文字标签独立保存；为拉近后的立面单独准备清晰细节。先做一栋或一组，不批量出整街。旧 skill 只作早期视觉参考，运行程序不依赖它；正式素材许可逐项核验，不能靠改写提示词替代授权。
- [ ] **1.3 处理三种状态。** ①街景：水、树、路面、行人及非任务建筑常彩，只有未打卡目标去色。②点楼：同一张地图平移并放大到立面，保留相邻建筑作参照；没有点位卡、详情窗或领奖遮罩，浏览不记打卡。③打卡：条件满足后原地还彩，用一行提示收卡；返回保留原缩放与浏览位置。
- [ ] **1.4 做江门自己的界面。** 用实拍中的骑楼比例、柱廊、题字和江岸方向建立辨识度，文字不烤进位图。远景只显示少量街名，近景才显示楼名、讲解和打卡操作。参考 [Vibe Design Tips](https://vibedesign.tips/) 的界面连续性和动效节奏，不复制其视觉皮肤。像素化建筑和图标，不牺牲正文可读性。
- [ ] **1.5 过样板验收再扩图。** 交手机竖屏可点预览、全景/近景/打卡后三态截图、一段连续录屏。连续操作两栋（无第二个真实锚点可用测试夹具）：点 A 不算到访；打卡 A 后 B 仍灰；A 后方树叶和柱间露出的街景前后同色；刷新仍记住；返回不跳回地图起点。支持减少动效、可读标签、大触区。由用户确认画风、拉近距离和上色范围。

## 2｜真实街区地图与统一数据底座

- [ ] **2.1 建点位总表。** 用稳定 `point_id` 串起名称别名、类别、经纬度及坐标系、入口/中心之别、开放状态、建筑轮廓、文化实体、讲解、卡片、来源、核验日期及审核状态。游客端不展示占位符、猜测门牌或失效商户。
- [ ] **2.2 接五类数据。** 点位与文化资源、史料与语料、讲解员、车位与客流时序、脱敏行为。先用公开资料形成可查的底稿，再向运营方获取非公开数据；缺某一类不阻断其他模块开发，但不能把模拟值当实测。交独立数据字典、样例、更新频率与责任人。
- [ ] **2.3 生成分段底图。** 用合规地图和控制点校对路口、河岸、桥、步行通道及设施；处理需求方 CGCS2000 与地图服务坐标差异，保留原坐标与转换说明。图上热点、视觉透视坐标与导航计算坐标分开。现场抽查不发生隔河到达、落点穿楼或路线穿墙。
- [ ] **2.4 扩到整街。** 按已核街段逐段制作和拼接，邻接关系不断裂；选择重点建筑做独立立面、遮罩、代表物和小卡，其他真实点位可简化呈现。正式知识图谱覆盖 ≥100 个点位，不等于必须制作 100 张独栋精灵图。
- [ ] **2.5 做数据维护。** 导入、去重、字段和引用校验、来源及素材授权、版本、增量更新、审核发布和回滚。CSV/JSON、UTF-8、北京时间 UTC+8；发布前检查地图数据和示意图适用的合规要求。

## 3｜原生微信导览、LBS、打卡与卡册

- [ ] **3.1 建小程序壳。** 确认独立小程序还是由「乐游蓬江」跳入；办妥 AppID、体验版权限、服务域名、隐私指引及用到的开放能力。竖屏安全区、分包、瓦片按需加载、弱网资源缓存；首页直接是地图。
- [ ] **3.2 四种进入方式。** 地图点选进入近景；微信扫码直达已校验的点位；在有条件场地试贴 NFC 并分别验 iOS/安卓，不支持时改用扫码；授权定位后提供到达提醒。拍照识别及低置信候选确认见第 8 节。所有入口复用同一 ID，不出现四份内容。
- [ ] **3.3 分开“浏览、到达、打卡、点亮”。** 拒绝定位也能浏览和听讲解。允许定位时结合精度、停留和冷却时间避免漂移重复提醒。游客选择是否自动讲解。服务端校验现场到达或有效现场凭证；游客在近景确认打卡。转发链接、远程点楼、拍出相似建筑均不能独立证明到访。
- [ ] **3.4 持久化收集。** 普通点打卡后立即上色并发小卡；若设多步任务，前置条件先说清。重复扫码、双击、掉线重试不重复发卡。卡册能回看卡片、代表物故事、取得地点与时间；按授权恢复进度。演示重置入口不进入生产。
- [ ] **3.5 拍照上传打卡（核心入口）。** 在建筑近景点「拍照打卡」，支持现场拍摄或从相册选图。AI 用授权实景照片比对立面，并识读馆名、街牌或门牌，与目标点位的名称、别名和地址核对；不拿像素画当识别底图。经游客同意，可用本次手机定位与已核点位范围比对，精度不足时不判定到访。分开判断「拍的是哪栋楼」与「是否到场」：照片或可辨地址指向目标，且定位或有效现场凭证通过，才自动打卡；仅认出楼可听讲解，不直接点亮。错楼、模糊、无定位或相邻楼难区分时，保留地图近景，提示具体重拍部位或改扫现场码，不误点亮。通过后回原镜头只给目标还彩，同一用户同一点只发一张卡。上传前说明用途和保存期限，不默认公开或用于训练；不以照片 EXIF 或手填地址作为到场凭证。
- [ ] **照片验收：** 用长堤分馆正面、馆名门匾、邻楼相似立面、远程上传的正确照片、低精度/拒绝定位、重复上传及上传失败分别实测；记录误认与漏认，现场验证阈值。未核实的逐户门牌不用于区分双骑楼。
- [ ] **验收：** 微信开发者工具 + iOS/安卓真机各走一次拒绝授权、地图浏览、扫码到站、真实定位、打卡还彩、退出再进、重复打卡。NFC 无法部署的点明确标注，不做假入口。

## 4｜文化故事、三语讲解与路线

- [ ] **4.1 图谱与故事。** 对齐建筑、人物、事件、文物/非遗、商户与地点；每条关系能回到史料。支持实体查询、关联推荐、多层探索、故事线生成与史实校验。在地图上从一栋楼转向另一栋，竖屏默认不展示挤满屏幕的关系网。至少一条完整可走、有来源、可听的故事线。
- [ ] **4.2 三语讲解。** 指挥侧负责文案与三语稿，正式生成服务按点位检索经审核史料，生成短/标准/深度讲解；校审普通话、粤语、英语后合成或配音。支持离线或专有云部署讲解词生成与 TTS，保存模型/服务版本与许可。讲解缺证据不补故事，语音不可用时可阅读文字。
- [ ] **4.3 随游播放和问答。** 手动播放/暂停/继续、进度、语速、字幕、讲解语言、迷你播放条；结合位置、朝向与停留时间调整，传感器不可用时允许手选。问答仅基于当前点位和史料，提供出处或明确暂无依据。验收锁屏/切后台的实际支持范围、弱网与中断恢复、三语真机听感。
- [ ] **4.4 三条可比较路线。** 收集兴趣、必去地点、时长、步行强度、出行方式；实际计算可达道路、开放时间及停留时长，生成不同侧重的三条可行路线。列点位顺序、距离、时间和推荐理由，游客能自行挑选、增删或调序。约束无解时解释，不硬凑三条。
- [ ] **4.5 游览中调整。** 下一站提示、到达、跳站、改道、重算、暂停、断点续游、完成回顾；具备数据时接入人流、天气。自驾纳入停车和返程取车，非自驾考虑步行、公交及可用接驳。以真实路网验时长、距离和过街路径，不用图上直线充当导航。

## 5｜真人讲解员与停车（正式服务，不再是点按钮演示）

- [ ] **5.1 讲解员匹配。** 接入真实人员资料、语种、评级、主题、可服务地点及排班。随手机语言预选，可手动切换；按地点、语种、时间、评价匹配。无可约时段给替代人选或 AI 讲解。
- [ ] **5.2 预约闭环。** 游客提交 → 讲解员/调度员确认或拒绝 → 提醒 → 服务完成 → 评价；支持改约、取消和进度查询。验证两人同时订最后一个时段不会重复占用；未获订阅授权仍可在「我的」查状态。后台沉淀服务画像、旺季负荷和淡季活动安排。
- [ ] **5.3 停车比较。** 接真实停车场入口、开放时间、价格、总位/当前余位、更新时间；展示未来到达时预计余位、步行距离及推荐理由。陈旧/故障数据显式标记，不显示成实时。
- [ ] **5.4 预测与联动。** 用授权历史数据按时间切分训练/测试，比较基础模型与改进模型；融合工作日、天气、节假日、活动，预测未来 1 小时；综合预计到达时间、余位数、空闲率、费用及步行距离排序。支持省时/少走、备选车场、错峰、导航到入口、停车后接续游览和返回取车。无可靠预测时退到基础查询。YOLO 仅在许可和摄像头条件满足时作为采集手段，不代替预测模型。
- [ ] **验收：** 用两种身份完成一次预约、一次冲突改约、一次评价；用不同到达时间比较两座车场，模拟满位和接口断连，能转到替代车场且游览路线随之更新。

**停车口径声明（H5 原型阶段3 + 后端契约 v1.1）。** `prototype-paper/` 已把阶段2的零依赖 JS 运行时（预测/推荐/理由/降级链 D0–D4）注入为本地降级路径，后端上线后只换数据源、不改页面结构。诚实性红线与回落判据：
- 合成数据一律标「模拟数据 / 示范数据」，不冒充实时；`available=false` 只显示静态车场信息（名称/总位/步行/费用/开放时段），余位不显示并标「实时余位暂不可用」。
- `available=true 且 degraded=true` 可显示预测，但须标注降级方式（`forecast_method=last_known` 即「沿用最近一次观测」）并显示 `updated_at`。
- `arrive_free=null` 按「暂无余位」处理，不得显示为 0；`score_breakdown[].raw` 可能为 null 需兜底；`transfer.feasible` 当前恒为 false，不得据此显示「可换乘接驳」。
- `generated_at` 三种语义：`lots.generated_at`＝运行时数据生成时刻；`recommendations.generated_at`＝预测签发截点 `min(数据装载时刻, arrive_at−30min)`；`forecast.issued_at`＝请求时刻。
- H5 判错错误码：`invalid_filter` / `invalid_field` / `invalid_timestamp` / `lot_not_found` / `too_many_requests`(429)；guide-bridge 原样透传全部参数、服务端唯一校验，前端拼错参数收 400、不静默回落默认值。
- 已知局限：当前仅 2 座合成车场，`总时间 = 驾车估算 + 停车 + 步行` 与步行距离强相关，故「省总时间 / 少走路」两偏好只改变综合分与权重说明、不改变排序（96 个时段暴力枚举 0 次翻转）。

## 6｜匿名反馈、运营后台、评估与隐私

- [ ] **6.1 接诉即办。** 游客/居民/商户提交分类、时间、地点、描述、图片、可选联系方式与建议部门 → 唯一编号及可查询的二维码 → 受理/分派 → 现场处理与完成照 → 反馈 → 处理速度、效果、态度三维评价；支持未解决重新处理。对外匿名，不是所有后台账号都能看联系方式。
- [ ] **6.2 权限和后台。** 区分游客、讲解员、现场处理人员、调度、史料审核和管理角色；点位/图谱/多语稿审核发布、排班、车场源、任务规则、工单、操作日志和回滚。查询二维码不能泄露隐私或成为公开修改凭证。限制采集位置、图片、联系方式的目的、保存时间、访问和删除。
- [ ] **6.3 实际效果。** 埋点区分推荐曝光、点击、采纳、完成、讲解播放、预约确认、错峰建议采纳；过滤测试和重复事件。月报统计响应时长、完成率、重复投诉与满意度，并把游客评价和实际行为并看；有合法可靠数据再评估商户转化，不用点击量替代成交。
- [ ] **验收：** 同一工单用提交人、无关人员、处理人分别查看；走通一次补处理；检查谁能看图和联系方式。运营报表能由脱敏明细复算。

## 7｜指标、真机实测、完整交付与上线

下表是需求目标，不是当前成绩。上线前先定分母、样本、设备、网络和观测窗口；浏览器截图或模拟数据不能代替实地结果。

| 要验的指标 | 正式目标 | 需要留下的证据 |
|---|---|---|
| 文化资源 | ≥100 个点位；语义推荐 CTR ≥25% | 去重后的覆盖表、有来源的关系、点击/曝光记录 |
| 路线 | 生成 ≤3 秒；采纳率 ≥40% | 请求耗时；按需求书用“按推荐路线游览并完成的人数 / 获得推荐路线人数”，不能用点了“出发”的人数替代 |
| 讲解 | MOS ≥3.8/5；匹配准确率 ≥90%；普通话＋至少一种外语或方言 | 三语交付按项目方案，保存游客评分、逐点抽检与错配记录 |
| 预约 | 在线使用率 ≥30%；平均确认 ≤30 分钟 | 运营方确认线上/线下分母，真实订单和确认时间 |
| 停车 | 未来 1 小时预测误差目标 ≤20%；错峰建议采纳 ≥25% | 原需求 MAE 公式单位是“车位”，目标写百分数：先与需求方书面定归一化分母，保留绝对车位 MAE 和约定百分比两列；按需求书口径复算综合评分 |
| 小程序 | 首屏 ≤2 秒；关键页响应 ≤1.5 秒（响应耗时取 P95）；核心可用率 ≥99.5% | 冷启动/关键请求真机数据，约定窗口内的监控记录 |

- [ ] **7.1 现场验收。** 带 iOS、安卓沿实地走完整条路线，检查朝向、路口、定位漂移、入口、立面辨认、扫码/NFC、语音、断网续游；验证大字、减少动效、触控可达性，以及同一设备无障碍地完成“看楼→打卡→返回”。
- [ ] **7.2 工程验收。** 数据导入、权限、重复预约/发卡、图片上传、后台审核、监控告警、峰值压测、备份恢复、接口失败降级；回归结果与已知问题可追溯。未达指标写实测值、差距、措施和复测结果，不改验收口径凑数。
