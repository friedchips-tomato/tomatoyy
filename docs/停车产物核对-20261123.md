## 六、发现与处置：Windows 换行符导致的 `git status` 误报

### 6.1 现象

第一次执行 `PYTHONPATH=src python scripts/report.py` 之后，`git status --porcelain` **不是空的**，报出 4 个已跟踪文件「已修改」：

```text
 M parking-forecast/artifacts/manifest.json
 M parking-forecast/artifacts/metrics.json
 M parking-forecast/artifacts/model.json
 M parking-forecast/artifacts/report.md
```

跑完 `pytest` 之后又多出一个：

```text
 M parking-forecast/runtime/test/fixtures/consistency.json
```

### 6.2 定性：**不是内容差异**

三种独立方法交叉验证，结论是**内容逐字节一致**：

```text
$ git diff --exit-code --quiet ; echo "diff_exit=$?"
diff_exit=0

$ for f in manifest.json metrics.json model.json report.md; do
    d=$(sha256sum "parking-forecast/artifacts/$f" | cut -d' ' -f1)
    h=$(git show HEAD:parking-forecast/artifacts/$f | sha256sum | cut -d' ' -f1)
    if [ "$d" = "$h" ]; then echo "$f IDENTICAL"; else echo "$f DIFFER"; fi
  done
manifest.json IDENTICAL
metrics.json IDENTICAL
model.json IDENTICAL
report.md IDENTICAL

$ git hash-object parking-forecast/artifacts/model.json
745ef96e1e51c0d2b97dc97f9dddf153a49a5fe5      # 与索引/HEAD 的 blob SHA 完全相同
```

### 6.3 根因

- 本仓库的管线（`src/pf/export.py`、`src/pf/synth.py`）用 `open(..., newline="\n")` **显式以 LF 落盘**（源码注释写明「生成物一律以 LF 落盘，不受平台默认换行转换影响」）。
- 本机 Git 的 `core.autocrlf = true`，检出时把仓库里的 LF blob 还原成 **CRLF** 工作区文件。
- 于是「工作区 CRLF vs 管线写出的 LF」在 `git status` 的**换行符归一化判定**里被判成「已修改」，而 `git diff`（按内容过滤后比较）判为无差异。

复核证据：

```text
$ git checkout -- parking-forecast/artifacts/        # 用 Git 自己检出（得到 CRLF）
$ for f in manifest.json metrics.json model.json report.md; do
    echo "$f CR=$(tr -cd '\r' < parking-forecast/artifacts/$f | wc -c)"
  done
manifest.json CR=231
metrics.json CR=743
model.json CR=657
report.md CR=111
$ git status --porcelain
（空）
```

即：**只要工作区保持 Git 检出的 CRLF 形态，状态就是干净的；只要管线以 LF 覆写，就会被判成「已修改」**，而内容没变。

### 6.4 处置：新增 `.gitattributes`（本次新增的仓库配置文件）

根因在仓库配置，不在业务代码，也不应改动 `artifacts/` 产物本身。因此新增了根目录 `.gitattributes`，把「管线以 LF 落盘」的两条路径固定为 LF 检出：

```gitattributes
# 生成物与测试夹具一律以 LF 落盘（管线用 newline=LF 显式写文件），
# 检出也保持 LF，避免 Windows 上 core.autocrlf=true 把 LF 文件误判为「已修改」。
parking-forecast/artifacts/** text eol=lf
parking-forecast/runtime/test/fixtures/*.json text eol=lf
```

处置后的实测（同一台机器、同一套命令）：

```text
$ git status --porcelain
?? .gitattributes                 # 只剩本次新增文件本身

$ cd parking-forecast && PYTHONPATH=src python scripts/report.py && python -m pytest tests -q
…
67 passed in 105.85s (0:01:45)

$ cd .. && git status --porcelain
?? .gitattributes                 # 重算 + 跑完全量测试后，已跟踪文件依然零改动
```

即：**在补上 `.gitattributes` 之后，「重算产物 → `git status --porcelain` 为空」这条验收从「需要手工还原」变成了「可重复成立」**，现场被追问时可以直接当场跑给评委看。

> 本次核对**没有修改、也没有提交** `parking-forecast/artifacts/` 下的任何产物文件；`git diff --exit-code` 为 0，产物与 HEAD 完全一致。
