# 长堤风貌街数据字典 v0.1

## 1. 交付范围

本版用于首次对接和样例核验，覆盖发榜方拟提供的五类数据。对接格式和频率是待确认建议，字段以仓库证据为准。

## 2. 版本与证据

工作树初始 HEAD 为 3717abf，实际交付数据与代码来源沿用 ebc0a82。涉及独立分支时，字段来源另记对应 Git ref 与文件。001–014 中的工单、监督、联系和报告表属于其他业务。

## 3. 类型、必填与计数

SQLite 类型按迁移列类型记载。JSON 类型按 schema，H5 依据原型及接入规则写明。必填指相应记录层级，允许 null 的字段单独标出。按表内行计数，嵌套字段各计一行，同名跨表重复计入，分支占位计入，坐标政策及文档元数据不计。

## 4. 交换与发布

供数包采用 UTF-8，保留源文件、来源和批次。对接与报表沟通采用北京时间 UTC+8，已有 SQL 与 schema 的存储时区规则按各自契约保留。缺字段、未核、无覆盖和 0 分开处理。

## 5. 五类数据接入

### 5.1 统一点位标识规范

- 建议点位总表以稳定的 point_id 作为接入关联键。H5 源字段是 id，已见 CD-R01、CD-V01、CD-A02、CD-S03、CD-P01。原型兼容入口按现有 CD、单个大写字母、两位数字的形态登记，形态校验为 ^CD-[A-Z][0-9]{2}$。字母业务含义、号码扩展规则及跨区规则待发榜方确认。
- 已分配编号保持唯一且稳定，名称更正不换号，停用编号留档。路线分支使用 LD… 作为 point_id 并保留 H5 的 source_point_id，例如 LD001 对应 CD-R01。图谱分支输入约束亦为 LD…。接入前审核映射表和未匹配项，不能按序号或相同名称直接拼接。
- 正式地理台账验收建议必填点位标识、name、category、longitude、latitude 和 coord_system，并随包提供坐标来源、入口或中心的口径及核验记录。出处与原始坐标要可追溯。这是 v0.1 接入建议，正式字段及必填性待发榜方确认。原型渲染侧校验 id 和 hotspot，不能自动补出经纬度。
- hotspot 的原点在 assets/map.jpg 左上角，x、y、w、h 都是底图百分比。地理坐标以经纬度十进制度登记，longitude 对应经度、latitude 对应纬度。停车 schema 的 geometry 采用 lon、lat 并允许 null。像素热点、地理点和建筑轮廓各自保存。
- 待澄清项。docs/像素地图方案清单.md:133、docs/方案清单.md:106 要求处理 CGCS2000↔GCJ-02，现有文字明确了需求方供 CGCS2000、小程序使用 GCJ-02 的入库换算方向。algo/route-recommender 分支的 route-recommender/data/points.json 则写明 WGS84 且样例坐标为 synthetic。三种口径原样记录，待发榜方与地图接入方确认原始坐标系、正反向转换要求、工具、允许误差及现场控制点后才执行转换，保留来源、原值及转换记录。

- 核验编号唯一、路线与故事引用可解析，parking 可回查车场目录。hotspot 各值有限，左上偏移非负，宽高大于零，右边和下边不超出底图。

#### 质量检查规则

- 校验 6 份 schema 的字段与必填项，区分车场、观测、信号、预测、推荐及交换产物。限制车场标识唯一，观测按 lot_id 和 ts 核查重复、时区和时序，信号的 ALL 仅作全局聚合键。
- free_spaces 若有值须在 0 和有效总位数之间。quality=missing 时 free_spaces 为 null，quality=stale 时必须带 age_seconds。预测区间与点预测受容量约束，null 保留不可用含义。
- 按 kind 检查信号字段，推荐按 score 降序，异常与缺失时核对降级原因。recommendation.schema.json 与 artifact.schema.json 描述交换形态，运行时推荐还有额外字段，内联模型也有独立校验入口，接入前明确采用的契约。
- 客流待确认统计断面、进出与去重口径、时间窗、采样频率及缺测标识，单独校验连续性。停车余位与活动信号不能代替客流实测。

## 6. 核验与更新流程
