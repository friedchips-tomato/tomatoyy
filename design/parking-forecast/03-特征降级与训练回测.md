# 03 · 特征、缺失降级、训练与回测

---

## 1. 特征表

预测目标：`target_ts`（默认 `issued_at + 60min`）时刻的 `free_spaces`。
预测粒度：每 15 分钟一个点，覆盖未来 60 分钟（4 点），与现行 `forecast: [12, 8, 10, 15]` 的形状一致，便于直接替换。

每个特征都必须满足：**在 `issued_at` 时刻可获得**（不含未来信息）。

| 组 | 特征 | 计算 | 缺失时 |
| --- | --- | --- | --- |
| **滞后余位** | `free_lag_1` / `free_lag_2` / `free_lag_4`（=15/30/60 分钟前） | 取该车场最近第 k 条 `quality=ok` 的观测 | 用 `free_known` + `known_age_min` 代替；再缺则置空并置 `missing_flag` |
| | `free_known` | 最近一条 `quality in (ok, stale)` 的观测值 | 无则 `null` |
| | `known_age_min` | `issued_at − 该观测 ts` | — |
| | `free_rate_known` | `free_known / total_spaces` | 同上 |
| | `drain_15` / `drain_60` | 最近 15 / 60 分钟的余位变化率（车位/分钟，正=减少） | 不足窗口则 `null` |
| **周期基线** | `same_slot_mean` / `same_slot_median` | 过去 4 周内、同一星期几 + 同一时刻（±15 分钟）的历史余位均值 / 中位数 | 样本 < 3 则 `null` |
| | `same_weekday_mean` | 过去 4 周内同星期几同一时刻均值（放宽到 ±30 分钟） | 样本 < 2 则 `null` |
| | `same_day_hist` | 今日更早时刻的余位中位数（当日已观测） | 无则 `null` |
| **日历** | `is_workday` / `is_holiday` / `is_weekend` | 来自 `calendar` 信号 | 信号缺失 → 用「工作日/周末」的**默认假设**并置 `calendar_missing=true`（**必须显式标记**，不能假装知道） |
| | `is_peak` / `peak_type` | 高峰时段标识与类型 | 同上 |
| | `days_since_holiday` / `days_to_holiday` | 距最近节假日天数（范围 −7..7） | 无日历 → `null` |
| | `time_of_day_sin/cos` | 时刻的周期编码（处理 23:00→00:00 环绕） | 恒有 |
| | `dow_sin/cos` | 星期几的周期编码 | 恒有 |
| **天气** | `weather_code` / `is_rain` / `temperature_c` | 来自 `weather` 信号 | 无天气 → `weather_missing=true`，天气类特征填**训练集众数**，不填 0（0 会被误读为"晴天无影响"） |
| **事件** | `event_strength` / `event_in_2h` / `event_size` | 来自 `event` 信号 | **无事件数据 ≠ 强度 0**：用 `event_missing=true` + 填训练集中位数，并在模型里用「缺失指示位」告诉模型 |
| **车场属性** | `total_spaces` / `base_rate`（车场历史平均空置率） | 静态 + 训练集统计 | 恒有 |
| | `day_of_history` | 该车场已有历史天数（冷启动程度） | 恒有 |
| **交互项（建议）** | `peak × is_workday`、`rain × is_weekend` | 显式构造少量交互，不做全量自动 | 同上 |

**关于"缺失指示位"**：所有可能缺失的特征组都配一个 `*_missing` 布尔位，直接参与训练。理由：把"没数据"编码成"某个数值"再让模型去猜，等于静默伪造。指示位让模型至少有机会区分"确实如此"与"不知道"。

## 2. 缺失与过期数据的降级策略

### 2.1 降级链（顺序固定，命中即停）

```
D0  model          —— 特征完整（无 *_missing 且有足够历史），用模型预测
D1  same_slot      —— 特征有缺失但历史充足 → 同星期同时段中位数（robust 基线）
D2  same_weekday   —— 同星期同时段样本不足 → 同星期几的更宽窗口均值
D3  last_known     —— 只剩最近已知值 → 直接用最后已知余位作为点预测（不外推趋势）
D4  unavailable    —— 连最后已知值都没有 → 点预测为 null，method=unavailable
```

**关键规则**：

- 每一级降级都在 `forecast.method` 与 `degrade_reason` 里留痕，页面与月报都能看到「这个数字是怎么来的」。
- **不静默伪造**：
  - `D3 last_known` **只复制最后已知值，不做趋势外推**。外推等于编造。
  - `D4` 时 `point_free = null`，UI 必须显示「暂不可用」，**不得显示 0**（0 会被理解为"满位"，是危险的假信息）。
  - 任何一级降级都不改变 `free_rate` 的分母（`total_spaces` 始终来自真实车场容量）。
- **过期判定用 `age_seconds`**，不用文案：
  - `age_seconds <= 180`（3 分钟）→ 视为实时；
  - `180 < age_seconds <= 900`（15 分钟）→ 视为「延迟」，点估计仍可用，但 `degraded=true` 且 UI 标注「数据延迟 X 分钟」；
  - `age_seconds > 900` → 视为过期，`point_free` 保留（用于趋势展示）但**不进入排序的主权重**，并在卡片上标注「数据过期，以现场为准」。
  - `quality=missing` 的观测**不参与**任何「最后已知值」——只有 `ok`/`stale` 才算。
- **陈旧优先于可用**：`quality=stale` 的观测可以用，但 `known_age_min` 会进入特征，且 `degraded=true`。

### 2.2 与现有运营台语义的对齐

`prototype-paper/ops.js` 现有的人工 `stale` 开关要保留为**人工覆盖**：人工标记 stale ⇒ 强制 `degraded=true`、不参与排序主权重、显示「已标记陈旧，游客端不显示为实时」。数据驱动的 `age_seconds` 判定是**新增的一层**，两者取或。

## 3. 训练与回测

### 3.1 时间有序切分（防泄漏）

**硬规则：任何特征、任何基线统计量，只能用 `ts <= issued_at` 的数据计算。** 这一点需要在代码结构上强制，而不是靠自觉：

- 特征构造函数签名固定为 `build_features(dataset, issued_at, cutoffs)`，`cutoffs` 是「允许看到的最晚观测时刻」。回测时 `cutoffs = issued_at`；线上时 `cutoffs = min(now, issued_at)`。
- 同周期基线（`same_slot_mean` 等）的统计窗口必须**以 `issued_at` 为右端点**回看，且**排除目标时刻及其之后**。
- 训练/验证/测试按**时间**切分，不随机打散：

```
train:      D1  .. D60   (前 60 天)
validation: D61 .. D75   (15 天)
test:       D76 .. D90   (15 天)
```

- **embargo（隔离带）**：切分点后留 24 小时不参与任何一侧的统计量计算，因为预测 horizon 达 60 分钟，若目标时刻跨过切分点会造成标签泄漏。
- **滚动回测（walk-forward）**作为主报告口径：对测试期内每一个 `issued_at`（按 15 分钟步进），用「该时刻之前的所有数据」训练/取基线，预测未来 60 分钟，累加误差。这是最贴近线上用法的口径。

### 3.2 基线（至少三个，必须全部实现并上报）

| 编号 | 基线 | 定义 |
| --- | --- | --- |
| B1 | `last_known` | 预测 = 最后已知余位（当前值持平假设） |
| B2 | `same_slot_baseline` | 预测 = 过去 4 周同星期几同时刻的**中位数** |
| B3 | `same_weekday_baseline` | 预测 = 过去 4 周同星期几 ±30 分钟窗口的**均值** |
| B4（可选参考） | `naive_no_change` | 与 B1 相同，但排除任何滞后量差异时作为上界参照 |

「前一日同时段」作为 **B2/B3 的补充诊断**（不进正式基线表，因为该街区尚未确认有稳定的跨日结构），在报告中单列一行观察。

模型必须**在同一切分上与基线对比**，只报模型自己的数字没有意义。

### 3.3 候选模型

按复杂度递增，逐级对照：

1. **M0 规则模型**：`same_slot_median` + 明确的时段修正（例如高峰线性微调）。作用是给出可解释上界。
2. **M1 岭回归 / Gradient Boosting（sklearn）**：输入 §1 的特征矩阵。`HistGradientBoostingRegressor` 处理缺失值原生，但仍按 §1 显式填值以保持与运行时一致。
3. **M2 分车场模型**：每车场单独模型 vs 全局模型 + `total_spaces` 特征，用回测决定（数据量小时全局模型更稳）。
4. **M3 区间预测**：用分位数回归（`HistGradientBoostingRegressor(loss="quantile", quantile=0.1/0.9)`）给出 `p10/p90`。

**运行时约束**：浏览器运行时不能跑 sklearn。因此训练结果必须**导出为可被 JS 解释执行的产物**。本方案的做法：

- 首选模型类型限定为**可导出**的：规则模型、线性模型（导出系数）、或**分箱查表**（把 `GBDT` 的树导出为 `if/else` 数组，JS 直接遍历）。
- 产物格式 `artifacts/model.json`：`{version, kind: "rules"|"linear"|"trees", features: [...], payload: {...}, trained_at, data_fingerprint}`。
- `kind: "trees"` 的 JS 解释器约 60 行，遍历节点比较阈值，输出叶节点值。**必须用与 Python 完全相同的样例做逐条比对测试**（Python 与 JS 对同一批输入输出必须逐位相等），否则会出现"训练能过、线上漂移"。

### 3.4 指标

在**余位（车位）**与**空置率（%）**两个量纲上分别计算：

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| MAE（车位） | `mean(|pred − actual|)` | 需求书原始口径（单位是车位） |
| RMSE（车位） | `sqrt(mean((pred − actual)^2))` | 对大误差更敏感 |
| MAPE | `mean(|pred − actual| / actual)`，**只在 `actual > 0` 上计算**，并单独报告被排除样本比例 | 百分比口径；`actual=0`（满位）时 MAPE 无定义，必须排除并披露 |
| WAPE | `sum(|pred − actual|) / sum(actual)` | 百分比口径的稳健版，建议作为主百分比指标 |
| 空置率 MAE（百分点） | `mean(|pred_rate − actual_rate|) * 100` | 与「空置率」直觉对齐 |
| 偏差 Bias | `mean(pred − actual)` | 看系统性高估/低估 |
| 命中率 | `P(actual ≥ pred)`（或 `|pred−actual| ≤ 1`） | 运营侧直观理解：「说的这个数有多准」 |

**必须分层报告**：按 horizon（15/30/45/60 分钟）、按车场、按工作日/周末、按天气、按有无活动、按数据质量（正常/降级）分别给出。整体一个数字会掩盖「雨天 60 分钟预测完全不准」这类问题。

### 3.5 ≤20% 目标与指标的对应关系（**这是最容易被糊弄的地方**）

需求文档写的是「车位预测 MAE ≤ 20%」，而 MAE 的自然单位是**车位**。`docs/长堤导览-从样板到上线总清单.md:71` 已经明确要求：*"原需求 MAE 公式单位是『车位』，目标写百分数：先与需求方书面定归一化分母，保留绝对车位 MAE 和约定百分比两列"*。

本方案照此执行，给出**待书面确认的两列口径**：

| 口径 | 公式 | 备注 |
| --- | --- | --- |
| A：相对平均余位 | `MAE_spots / mean(actual_free)` | 分母是「平均真实余位」，直观但**分母会随拥挤程度变化**（满位时段分母趋 0，比例爆炸） |
| B：相对总车位 | `MAE_spots / total_spaces` | 分母稳定；但对 80 位与 120 位车场一视同仁，大车场容易达标 |
| C：空置率 MAE | `mean(|pred_rate − actual_rate|) * 100`（百分点） | 与「空置率」直觉一致，单位是百分点 |
| D：WAPE | `sum(|e|) / sum(actual)` | 聚合稳定，推荐作主百分比口径 |

**报告必须同时给出绝对车位 MAE 和选定口径的百分比**，并在报告首页写明选了哪一口径、为什么。

**「≤20%」的达标判定（合成 vs 正式，严格分开）**：

| 层级 | 判定 | 依据 |
| --- | --- | --- |
| **合成验收** | 在合成数据上，模型在**主口径**上的误差**显著优于最强基线**（例如 MAE 相对 B2 下降 ≥ 10%，且各 horizon 分层无某一层比最强基线更差），并且**管线正确性**全部通过（无泄漏自检、降级路径全覆盖、Python/JS 输出一致） | 合成数据由我们自己定义，误差水平由我们设定，**因此合成数据上的任何百分数都没有对外意义** |
| **正式达标** | 在**真实历史数据**上：按书面确认的分母口径，主指标 ≤ 20%，且**分层后无关键分层严重劣化**（建议：工作日/周末、峰/非峰、每个车场的 WAPE 均 ≤ 阈值），并经**现场校验**（见 §5） | 唯一有意义的达标路径 |

一句话写进报告页脚：**「本结果基于合成数据，仅证明管线可用，不代表模型精度。正式精度指标必须由真实历史数据与现场校验得出。」**

### 3.6 回测报告产物

```
artifacts/
  metrics.json      # 分层指标 + 基线对比 + 口径声明
  report.md         # 人读报告：口径、结论、限制、未达标项
  manifest.json     # 数据指纹 + 模型版本 + 随机种子 + 生成时间
```

`report.md` 必须包含：**分母口径声明**、绝对 MAE 与百分比两列、基线对比表、分层表、降级路径覆盖统计、泄漏自检结果、以及"这是合成数据"的显著声明。

### 3.7 泄漏自检（自动化，进 CI）

必做断言（失败即阻断）：

1. **未来信息断言**：随机抽 200 个 `issued_at`，把 `issued_at` 之后的所有观测从数据集中删除，特征与预测结果必须**完全不变**。
2. **同周期基线右端点断言**：`same_slot_*` 的统计窗口右端点 `<= issued_at`。
3. **切分隔离断言**：train 集的最大 `ts` < validation 集的最小 `ts` − embargo。
4. **Python/JS 一致性断言**：同一批 500 条输入，Python 模型与 JS 运行时输出逐位相等。
5. **降级覆盖断言**：合成数据中每一级降级（D1..D4）在回测里都被触发过，且每级的指标单独统计。

## 4. 冷启动

新车场（无历史）时：

- `day_of_history = 0` → 强制 D1 起步，且 `same_slot_*` 全为 null → 实际落到 D2/D3。
- 若连 D3 都没有 → `unavailable`，UI 显示「该车场暂无可靠余位」，**不显示数字**。
- 新车场不参与 MAE 达标判定（无历史基线可比），但在报告中单列「冷启动车场」表现。

## 5. 现场校验（正式达标的必要条件，合成不可替代）

模型精度最终要靠现场对照确认，方案中预留（实现阶段做工具，不在本任务做）：

- **抽样对照法**：运营人员在随机时刻记录实际余位（现场计数或闸机系统），与同一时刻的预测值配对，形成「现场校验集」。该集合是**唯一能宣称"预测误差"的证据**。
- **到达核验**：`parking_arrival_verified` 事件（另一分支已有类型定义）天然可作为核验来源 —— 游客按推荐到达后，核验其车场余位与预测是否一致。这条路径需要真实的核验来源（闸机/人工/第三方），目前**没有**。
- **现场校验集不得用于训练**，只用于评估，避免自我印证。

## 6. 依赖与顺序

```
schema → synth → dataset 读取层 → features → baselines → split/回测框架
      → 训练(M0..M3) → export 产物 → JS 运行时解释器 → 一致性测试 → 回测报告
```

**模型 → 运行时**这条链是本任务最容易出事的环节：训练在 Python，推理在 JS。因此：

- 产物格式在设计阶段就固定（`artifact.schema.json`）；
- 一致性测试（§3.7 第 4 条）写进阶段验收，不允许"先上线再对齐"。
