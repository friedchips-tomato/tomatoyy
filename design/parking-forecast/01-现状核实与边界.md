核实到的结构事实：

| 字段 | 事实 |
| --- | --- |
| `total` / `free` | 写死。P1: 120/18，P2: 80/41 |
| `walk` | 写死，单位**米**（150 / 450），不是时间 |
| `fee` | 写死字符串（"5 元/小时"），无法参与计算 |
| `updated` | 写死**相对文案**（"2 分钟前"），不是时间戳 → 无法判断过期、无法做降级 |
| `past` | 写死 5 个历史余位值，**无时间戳**，不知道步长（分钟？）和覆盖窗口（过去多久？） |
| `forecast` | 写死 4 个未来值（1 小时 = 4 点 → 推断步长 15 分钟），**无时间戳、无误差区间、无生成时间** |
| `reason` | 一句人话结论，无可复算依据 |
| 车场数量 | 只有 2 个（P1、P2） |

`points.js` 中 `point.parking` 指向车场 id（`points.js:167` 有一个点位引用 `P1`）；`prototype-paper/check.mjs` 会校验 `point.parking` 必须存在于 `parking` 数组。

## 4. 模块放置位置：独立目录 vs 并入 `changdi-intake`

### 4.1 候选与理由

| 方案 | 优点 | 缺点 | 判断 |
| --- | --- | --- | --- |
| **A. 独立顶层目录 `parking-forecast/`** | 不碰 `changdi-intake` 的 SQLite、迁移、`user_version`、鉴权、月报口径；Python 依赖（numpy/pandas/sklearn，本机已装：1.26.4 / 2.1.4 / 1.8.0）与 Node 零依赖栈互不污染；训练产物可单独版本化与复现 | 需要自己定义与导览侧的对接契约 | **采纳** |
| B. 并入 `changdi-intake/server/src/parking/` | 复用现有 HTTP/鉴权/SQLite | 要在 `node:sqlite` 里做时间序列与训练，Python 侧模型无法直接复用；训练/推理依赖会污染接诉即办的零依赖交付物；迁移版本号（现 `SCHEMA_VERSION`）与回测数据集耦合；回归基线 98 项测试全部受牵连 | 不采纳 |
| C. 并入 `prototype-paper/` | 前端读取方便 | 训练代码与演示页混在一起；`prototype-paper` 现在的定位是「原生 HTML/CSS/JS，不装依赖」，引入训练脚本会破坏该约束；真实数据也不能放进演示目录 | 不采纳 |

1. `parking-forecast` 产出 → 导览侧通过**静态产物文件 + 运行时脚本**读取；

## 5. 与现有导览侧的衔接方式（可插拔，不依赖未落地代码）

由于 §1 的关键结论 A，本任务必须假设「导览事件通路」**可能不存在**。因此：

- 停车预测结果以**产物契约**（`schemas/artifact.schema.json`）交付：一份带 `generatedAt` / `modelVersion` / `dataFingerprint` 的 JSON。
- 导览侧读取产物的方式：**页面运行时读 `window.CD_PARKING_ARTIFACT`**（由一个可选的小脚本注入），缺省时回落到现有静态 `data.parking`（保持「示范数据」标注与现有视觉）。这样：
  - 产物缺失 / 版本不兼容 / 字段缺失 → 明确显示「预测不可用」，**不静默伪造**；
  - 事件上报用 `window.CD_TOURISM?.record?.(...)` 的**可选链**调用（与另一分支的写法一致），`CD_TOURISM` 不存在时静默跳过，不报错、不阻塞 UI。
- 这样本任务在「导览事件通路已落地」与「尚未落地」两种世界下都能工作，不需要把两者绑死。

## 8. 核实到的事实清单（供总控直接引用）

1. 停车数据是 2 个车场的静态字面量，含写死的 `past`/`forecast`/`reason`，`updated` 是相对文案不是时间戳。
2. `parkingCard`/`parkingChart` 直接画这些值；`parking-start` 只打开路线表单，本分支**不产生任何事件**。
3. 路线侧三条路线是预设数据，排序靠兴趣命中与时长接近；自驾模式仅把车场插到首位。
4. 本分支**没有** tourism 事件模块；它只存在于 `intake-guide-collection` / `D:` checkout 的**未提交**工作区。
5. `changdi-intake` 是零第三方依赖的 Node 22 + `node:sqlite` 服务，鉴权已支持「同令牌跨来源即启动失败」，是独立凭据要求的落点。
6. 月报里的 tourism 目前是硬编码 `unavailable`；覆盖状态机制在另一分支的未提交实现里。
7. 导览侧事件目录在服务端与客户端各有一份，新增车场必须同步两处。
8. `prototype-paper/ops.js` 已有「陈旧车场」的人工开关与展示口径，可复用其视觉语义，但判定必须改为数据驱动。
9. 文档口径矛盾已存在：`docs/长堤导览-从样板到上线总清单.md:71` 已写明「原需求 MAE 公式单位是『车位』，目标写百分数：先与需求方书面定归一化分母，保留绝对车位 MAE 和约定百分比两列」。本方案沿用该口径。
