# 长堤风貌街接诉即办本地验收手册

先用自动化验收确认一张工单能走过三个窗口对应的后端操作，再用同样的角色顺序演示当前小程序页面。全程用合成数据和本地测试身份。微信界面、真机和合作方平台各自记录验收结果。

## Windows 验证命令

在仓库根目录打开 PowerShell。后端要求 Node.js 22.17 或以上，使用内置 SQLite。两条默认测试命令分别跑后端和小程序全量用例。需要 HTTP 的测试自行创建临时库和回环随机端口，无需启动演示服务或配置账号。

~~~powershell
node --version
npm.cmd --version
npm.cmd --prefix .\changdi-intake\server test
npm.cmd --prefix .\changdi-intake\miniprogram test
~~~

只重查三窗口同单主线时，可执行 `node --test .\changdi-intake\server\test\three-window-acceptance.test.js`。

## 手动演示准备

1. 在用于合成演示的 PowerShell 会话中进入 `changdi-intake/server`。按 [README 本地运行](../server/README.md#本地运行) 生成当前会话的接入方、值班、承办、主管及两家商户测试身份，再执行其中的 `npm.cmd start`。配置引用 README 中的临时生成方法，手动演示沿用 README 给出的角色和商户编号，使用本机临时生成的测试令牌。
2. 手动启动默认使用 `127.0.0.1:3400` 和工作区内的 `server/.local/intake.sqlite`，该库会跨重启保留。仅在确认是本人的专用演示库时复用，搭配原来的回执密钥。首次演示优先使用独立工作副本和空库。发现共享库或其他人已占用端口时，继续用自动化临时实例验收，或在独立工作副本安排手动演示。改端口时同步该副本的小程序基址。
3. 在同一台 Windows 电脑上，用微信开发者工具导入 `changdi-intake/miniprogram`，入口为首页三个窗口。默认配置使用游客 AppID 占位标识和回环基址。使用工具的本地模拟器，管理方用回环模式下的合成工作人员令牌登录，每次操作按所需角色退出后再切换身份。普通手机访问自己的 `127.0.0.1`，因此真机走查须使用单独配置的 HTTPS 测试环境。[小程序配置](../miniprogram/config.js) · [项目配置](../miniprogram/project.config.json)
4. 用 [README 合作方联调](../server/README.md#合作方联调) 的本地 multipart 请求创建演示工单。首次提交和原样重试使用同一个外部单号、正文和附件。新一轮独立演示使用新的合成外部单号。记下工单编号和公开查询码。本人核验用当次回执的私密凭证，按 [联调样例的回执规则](./integration-examples.md#5-外部平台如何展示回执) 在提交人会话内暂存。README 示例默认只显示状态、编号和公开码。需要在本机演示私密核验时，可把示例最后一行改为 `process.stdout.write(JSON.stringify(receipt))`，将整个 PowerShell 管道赋给临时变量 `$demoReceipt` 并在末尾接 `| ConvertFrom-Json`，使回执进入当前会话变量。仅让原提交人在私下录入，截图、转发和日志只保留脱敏证据。

## 一张工单的演示顺序

贯穿主线使用同一个 `caseNumber`。用合成路面松动事项，省略联系方式，给商户单独填写合成协办地点。文字补件和图片步骤可插入这张工单。下列页面操作根据当前源码整理，实际点按结果按所用环境留证。

| 顺序与角色 | 怎么做 | 应观察到的现象 |
| --- | --- | --- |
| 1 合作方代匿名提交人 | 发送一次申报，再原样重试。 | HTTP 首次为 201，重试为 200，三字段回执一致，待受理只增加一张。正式小程序码待接入，演示使用回执的公开查询码。 |
| 2 匿名提交人／普通访客 | 进入「游客与居民」，手动输入公开码查询。 | 仅见工单编号、当前状态及可公开时间节点，初始为已提交。 |
| 3 值班 `desk` → 原提交人 → 值班 | 值班在待受理详情点「要求补材料」，填写如「请补充发生时段」。原提交人重新查询并用私密凭证核验，在「补充材料」填写说明，可通过「选择补件照片」添加合成图片，再点「提交补件」。 | 工单先移出待受理。本人可见补件要求和提出时间，提交后原编号、原轮次回到待受理。公开页只有状态和时间节点，补件原因与说明不会出现。授权本人及管理人员可按需查看补件图。演示使用外部申报单。 |
| 4 值班 `desk` | 刷新待受理并打开原单，点「受理」「分派」，选 `handler-a` 和未来期限。在详情的「协办任务」中点「派发协办」，填写 `shop-a`、说明、未来期限及必要地点。 | 原单从已受理到已分派。「协办任务」显示新任务。派发增加主单版本，任务从自己的初始版本开始。 |
| 5 店 A `shop-a`、店 B `shop-b` | 分别用自己的本地令牌进入商户工作台。查看「本商户工单」和「协办待办」。用店 A 打开获派任务并提交协办说明，可选合成照片。 | 这张外部工单只在店 A 的协办待办出现。详情显示任务说明、期限和必要地点，原单正文、联系方式、回执均不在其中。店 B 列表无任务，HTTP 直接查任务返回 404。 |
| 6 主管 `lead-a` → 店 A → 主管 | 主管在管理详情的「协办任务」中点「退回补充」并写原因。店 A 查退回原因并重新提交文字，主管刷新后点「通过协办」。 | 退回、再次送审和通过只更新协办版本。主单保持已分派及步骤 4 派发后的版本。在有效任务内，获派商户和获授权的当前承办人、主责主管可按需查看协办原图。 |
| 7 承办 `handler-a` → 主管 `lead-a` | 承办接单，在「提交办理结果」填写说明，点「选择办理照片」选择 1–3 张本地合成 JPEG、PNG 或 WebP，每张至多 5 MiB，再确认送审。要走文字分支可改填缺照原因。主管从待复核详情打开「承办送审原图」并点「查看」。 | 送审后为待复核，主管与当前承办可按授权查看原图；公开页仍只展示脱敏进度。值班人员无原图权限。送审超时或冲突时先刷新详情确认结果。 |
| 8 主管 `lead-a` | 点击「发布图片反馈」，填写反馈文字，点「选择 PNG 文件」，上传 1–3 张另存的脱敏合成图。逐张核对后打开人工脱敏确认开关，再点确认发布。也可单独使用「发布文字反馈」走文字分支。 | 图片走独立发布，不能引用送审原图。PNG 须为 8 位 RGB、非隔行，长宽各至多 2048 像素、每张至多 5 MiB。直接上传原图或未确认脱敏应被拒绝；成功后为待评价。本人核验后可点「查看第 … 轮第 … 张反馈图」，读取已发布的脱敏图。 |
| 9 原匿名提交人 → 主管 | 本人核验后查看该轮反馈，对速度、效果、态度评分，点「确认解决」。随后在期限内申请补办，由主管在补办队列点「通过补办」并重新分派。 | 评分后仍待评价，确认解决后已办结。批准补办后原编号进入第 2 轮并回到已分派。第 1 轮反馈和评分保留，第 2 轮尚无反馈。 |

内部调用和权限参考 [本人核验与操作](../server/README.md#本人核验详情和操作)、[管理办理和补办审核](../server/README.md#管理办理和补办审核) 及 [管理侧协办](../server/README.md#管理侧协办)。

### 商户新诉求与断网冻结

这一段用另一条合成事项，便于核对工单归属与重试去重。

1. 店 A 登录后，在「提交新诉求」点「新建」，填写发生日期和时间、地点、事项分类、诉求说明，联系方式和照片选填。正常提交后核对回执编号及状态。店 A 可在「本商户工单」刷新、筛选并查看详情，店 B 查不到这张工单。
2. 对另一条文字草稿，在隔离演示中模拟提交请求断网或超时，保持当前页面和会话。结果未知时字段及「清空重填」锁定，请求号保留；恢复连接后点「重试确认」，沿用原请求号及字段。提交已落库但回执丢失时，重试应返回原单，本商户工单只增加一张。仍无法确认时先查本商户工单列表。离开页面或退出后，冻结的会话不能续接，需先核对列表再决定是否提交。
3. 演示带图重试时，选图与文字一并冻结，恢复后按原请求重试。真机的图片选择、预览、上传及授权变化仍须走查。[商户页面源码](../miniprogram/pages/merchant/index.wxml) · [管理页面源码](../miniprogram/pages/staff/index.wxml) · [公众页面源码](../miniprogram/pages/public/index.wxml)

### 实测顺序

1. **先验环境。** 核对体验版版本、项目 AppID、微信合法 HTTPS 请求域名和合作方测试接口地址。项目方检查真机可达性、正式身份绑定及角色权限，并验证私有存储只允许获授权读写。
2. **验唯一接单接口。** 外部平台通过实际测试表单匿名提交合成数据和照片。双方核对成功回执与管理方待受理列表，首发 201，模拟回执丢失后以原单号和原内容重试得到 200 和同一工单，改变内容重用单号得到 409。记录脱敏工单号、接口状态、时间、构建版本和结果。详情、补件、评价、补办在小程序办理。[接口契约](./openapi.yaml) · [联调样例](./integration-examples.md)
3. **验真实码和真机。** 本轮版本接通实际小程序码后，由平台展示回执，另一台设备或另一账号扫描，确认落到同单且仅见编号、状态和可公开节点。原提交人另行输入私密凭证，验证仅自己可操作本人事项。按上文走完角色流程，记录选图、上传、复核、授权查看以及跨店拒绝；有模板且用户授权时再验反馈通知。
4. **验试点及外部来源。** 按确认的办理期限走真实测试角色，验证附件撤权、保留与恢复。先验月报汇总授权和数据缺失提示，导览来源到位后再对照其实际样例复算。[试点与上线清单](./implementation-checklist.md#七真机试点与发布门槛)

默认小程序配置仍使用游客 AppID 和本机 HTTP，后端使用本地测试身份和 SQLite。正式 HTTPS、微信小程序码和工作身份登录已有接线，并使用合成数据和模拟上游验证。体验版需配置获授权 AppID、HTTPS 合法域名、后端微信凭据和已批准身份，再验真实换码、发码及扫码。私有对象存储须在正式环境另行接入和验收。导览源未接入时显示数据缺失。[本地入口](../server/src/main.js) · [小程序环境切换](../miniprogram/README.md) · [存储及后续工作](../server/README.md#本地存储和下一批) · [内部月报](../server/README.md#内部月报)

### 保密验收结果

- 同单回环测试使用合成联系方式和照片。公开进度仅返回工单号、状态和时间节点。管理详情不返回联系方式，未获授权的账号读取补件、承办、协办及发布照片会被拒绝。测试检查回执及图片响应包含 `Cache-Control: no-store` 和 `Referrer-Policy: no-referrer`。发布照片按轮次授权读取，原始附件分开保管。[同单验收](../server/test/three-window-acceptance.test.js)
- 本地 SQLite 将联系方式和图片分表保存，数据库与备份文件仍可包含明文数据。正式验收需要验证主机目录和服务账号权限、数据库与备份静态加密、私有对象存储和附件撤权，并确认保留期限和恢复演练。还需要以实际网关和合作方配置验证访问日志不保留回执凭证、令牌、请求正文或私人图片，以及正式 HTTPS 的证书和网络行为。

## 关闭服务与保护数据

手动启动前查看端口归属。如果已有进程在监听，先确认实例是否归当前演示所有。启动自己的服务后记录同端口的 `OwningProcess`。演示结束在启动服务的终端按 Ctrl+C，等待返回提示符，再重复查询。默认端口示例，改过端口则使用实际值。

~~~powershell
$demoPort = 3400
Get-NetTCPConnection -State Listen -LocalPort $demoPort -ErrorAction SilentlyContinue |
~~~
